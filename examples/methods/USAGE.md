# 실행 가능한 작은 방법 모음

표준 라이브러리만 사용하는 독립 구현이다. 필요한 함수의 입력·보장 범위를 확인한 뒤 실제 문제에 맞춰 사용한다. 이 폴더의 함수가 제공하는 계약과 실제 업무 조건이 다르면 모델을 수정하고 다시 검증한다. 특정 함수가 실행됐다는 사실은 데이터 해석·웹 연결·전체 요구 충족의 증거가 아니다.

## 실행과 검산

저장소 루트에서 사용 가능한 Python으로 실행한다. 명령은 합성 예시를 출력하거나 메모리에서 검산하며 파일을 다운로드하거나 결과 파일을 덮어쓰지 않는다.

```bash
python -m examples.methods.demo
python -m unittest tests.test_method_examples -v
```

실제 사용 환경의 Python 버전과 실행 결과를 기록한다. 여기서는 최소 힙·deque·bisect 등 오래된 표준 API만 사용하며, 외부 최적화 패키지를 설치하지 않는다. 폴더의 Python 파일을 직접 실행하는 대신 모듈 명령을 사용한다. 애플리케이션에서는 필요한 함수를 가져온다.

```python
from examples.methods.graphs import dijkstra

distance, parent = dijkstra(
    4,
    [(0, 1, 4), (0, 2, 1), (2, 1, 1)],
    source=0,
    directed=True,
)
assert distance == [0, 2, 1, None]
```

이는 방향 그래프의 비음수 비용 경로 예제다. 숫자의 단위는 호출자가 정한다. 거리와 시간을 섞거나, 정류장·주소 같은 업무 ID를 정수 인덱스로 바꾼 대응표를 잃어버리지 않는다.

## 공통 입력 계약

- 숫자는 별도 설명이 없으면 Python `int`다. `bool`, 실수, `NaN`, 숫자 문자열을 정수로 자동 변환하지 않는다. 날짜·단위·결측의 변환은 입력 계층에서 명시적으로 한다.
- 배열과 간선은 `list` 또는 `tuple`이다. 임의 이터레이터·파일·URL·DataFrame을 직접 받지 않는다.
- 그래프 정점은 `0..node_count-1`. 간선은 `(from, to)` 또는 `(from, to, weight)`다. 중복 간선·자기 연결의 의미는 아래 표를 따른다.
- 잘못된 형식·범위는 `ValueError`다. 도달 불가나 유효한 부분 결과는 입력 오류와 구분한다.
- 함수는 전달된 목록을 수정하지 않는다. `Fenwick`과 `DisjointSet`은 메서드 호출로 내부 상태가 바뀌는 자료구조다. 내부 배열을 직접 수정하거나 잠금 없이 여러 요청이 함께 갱신하지 않는다.
- 동률은 정해진 순서로 처리하지만 업무상 공정성을 보장하는 규칙은 아니다. ID 변경에 무관한 공정성·무작위 추첨·순환 배정이 필요하면 별도 정책으로 정한다.

## 구현된 방법과 경계

`V`는 정점 수, `E`는 입력 간선 수, `n`은 항목 수, `C`는 정수 용량, `S`는 열거할 선택 조합 수, `B`는 탐색 평가 예산이다. 시간 복잡도는 아래 구현의 주요 항을 뜻하며 Python 객체 메모리와 큰 정수 연산 비용도 실제 규모에서 확인한다.

| 파일·이름 | 해결하는 부분과 반환 | 적용 조건·중요한 경계 | 비용 |
| --- | --- | --- | --- |
| [graphs.py](graphs.py) `bfs` | 동일 비용 간선의 최소 이동 횟수. `(distance, parent)` | 기본 무방향. `directed=True`면 방향 유지. 도달 불가 `None`, 시작점 부모 `None`. 중복·자기 연결 허용. 빈 그래프에는 유효한 시작점이 없어 거절 | 탐색 `O(V+E)`; 결정적 순서를 위한 이웃 정렬 비용 추가. 메모리 `O(V+E)` |
| `dijkstra` | 비음수 정수 비용의 최단거리·부모 | 기본 방향 그래프. 0 비용·평행 간선 허용, 음수 간선 거절. 동률에는 기존 부모 유지. 모든 정점을 방문하는 순회나 자원 배정 문제를 해결하지 않음 | 이웃 정렬과 힙을 포함한 보수적 상한 `O((V+E) log(V+E+1))`, 메모리 `O(V+E)` |
| `topological_sort` | 선행 관계를 지키는 정점 순서 | 방향 사이클이 있으면 `ValueError`. 여러 순서 중 인덱스 기준 사전순 최소. 중복 간선도 진입차수와 함께 일관되게 처리. 빈 입력은 `[]` | `O(E+V log(V+1))`, 메모리 `O(V+E)` |
| `DisjointSet` | 집합 합치기·같은 연결 성분 확인 | `union`은 실제 합쳐졌는지 반환. 경로 압축·크기 기준 합치기. 연결 해제·경로 거리 질의는 지원하지 않음 | 초기화 `O(V)`, 합치기·찾기 상각 `O(α(V))` |
| `minimum_spanning_forest` | 무방향 그래프의 최소 비용 연결 숲 | 음수 비용 허용. 자기 연결은 선택되지 않음. 평행 간선 허용. `components > 1`이면 하나의 연결 트리를 얻은 것이 아님. 빈 그래프 성분 수 0 | 간선 정렬 중심 `O(E log(E+1)+V)`, 메모리 `O(V+E)` |
| [sequences.py](sequences.py) `prefix_sums` | 고정 배열의 누적합. 길이 `n+1` | `[l,r)` 합은 `p[r]-p[l]`. 변경된 원본의 과거 누적합을 재사용하지 않음. 음수 원소 허용 | 준비 `O(n)`, 유효 범위 질의 `O(1)`, 메모리 `O(n)` |
| `Fenwick` | 점 하나 더하기와 구간 합 | `add(i, delta)`, `prefix(end)`, `range_sum(start,end)` 모두 0 기반·반열린 범위. 빈 배열의 빈 구간 합 0. 구간 최솟값·임의 구간 일괄 갱신은 이 구현의 계약 밖 | 이 구현의 초기화 `O(n log(n+1))`, 갱신·질의 `O(log(n+1))`, 메모리 `O(n)` |
| `sliding_maximum` | 고정 길이 창의 최댓값 | 완전한 창만 반환. 폭은 양의 정수, 배열보다 길면 `[]`. 비슷한 이름의 이동평균·가변 창 문제와 구분 | `O(n)`, 보조 메모리 `O(min(n,width))`와 출력 |
| `merge_intervals` | 겹치는 반열린 구간의 합집합 표현 | 정수 `start < end`. `[0,2)`와 `[2,4)`는 기본값에서 별도; `merge_touching=True`면 합침. 병합 결과로 예약별 소유자·개수를 복원할 수 없음 | `O(n log(n+1))`, 메모리 `O(n)` |
| `weighted_interval_schedule` | 단일 자원에서 비겹침 구간의 가치 합 최대 | `(start,end,value)`, 비음수 가치. 끝=다음 시작 허용. `{value, indices}`의 인덱스는 원본 목록 기준, 반환 순서는 실행 시각 순. 동률이면 새 항목을 추가하지 않는 기존 DP 선택 유지. 여러 자원·준비시간·선행 관계는 별도 모델 필요 | `O(n log(n+1))`, 메모리 `O(n)` |
| `knapsack_01` | 항목별 한 번만 선택, 용량 안에서 가치 합 최대 | `(positive_weight, nonnegative_value)`. 용량과 무게 정수. 0 무게·분할 가능 항목은 계약 밖. `{value, weight, indices}` 반환. 동률이면 뒤 항목을 추가하지 않음 | 시간·메모리 `O(nC)`인 의사다항식. DP 셀 수가 기본 100만을 넘으면 생성 전 거절; 호출 상한 최대 1천만 |
| [allocation.py](allocation.py) `bipartite_matching` | 허용 연결에서 일대일 최대 개수 배정 | `adjacency[left]`와 오른쪽 개수. 미배정은 `None`. 중복 후보는 제거. 비용 최솟값·여러 좌석·묶음 조건은 이 함수가 최적화하지 않음 | 좌측 수 `L`, 우측 수 `R`에서 후보 정렬 후 보수적으로 `O(L(L+R+E))`, 메모리 `O(L+R+E)` |
| `maximum_flow` | 단일 종류 흐름의 최대량과 컷 증거 | 비음수 정수 용량. 서로 다른 시작·종료점 필요. 평행 간선은 용량 합산, 반대 방향 간선 허용. 반환 `flows`는 합산된 방향 간선별 흐름; 원래 평행 간선별 분해는 별도. 최소 비용·고정 사용료·다품종 흐름은 지원하지 않음 | Edmonds–Karp `O(VE²)`에 초기 정렬·초기화 비용, 메모리 `O(V+E)` |
| `exact_capacitated_assignment` | 작은 단위 수요 배정의 독립 기준값 | 비용 행렬의 `None`은 금지. `배정 수 최대 → 비용 최소` 순서. 항목마다 한 자원의 용량 1 사용. 방문 순서·운행 개시비·시간표는 모델에 없음. 최적 부분 결과도 `complete=False` | 최악 `O(S(n+m))`, 메모리는 후보·현재 배정에 비례. 항목 200 이하·기본 조합 20만 이하만 열거, 호출 상한 최대 100만 |
| [local_search.py](local_search.py) `improve_tour` | 고정 방문 집합의 닫힌 순회를 구간 뒤집기로 개선 | 완전한 비음수 정수 비용 행렬과 전체 인덱스 순열. 방향별 비용을 매번 전체 재계산. 첫 정점 고정, 미방문·정원·시간창·픽업 관계는 다루지 않음 | 평가 최대 `B`, 각 평가 `O(n)`, 총 `O(n²+Bn)`. 기본 평가 1만, 호출 상한 100만 |

메모리·상태·평가 한도는 이 예제의 계산 방어 장치다. 더 큰 업무 문제를 모델링하거나 자료구조를 바꿔 풀 수 없다는 뜻이 아니다. 큰 입력에서는 실행시간을 별도로 측정하고, 계산을 멈춘 상태를 최적·불가능으로 바꾸어 설명하지 않는다.

## 결과를 오해하기 쉬운 사례

### 선택지가 적은 대상의 자리를 먼저 써 버린 경우

```python
from examples.methods.allocation import bipartite_matching

result = bipartite_matching([[0, 1], [0]], right_count=2)
assert result == {"assignment": [1, 0], "matched": 2}
```

왼쪽 첫 항목은 오른쪽 0·1 모두 가능하고 두 번째는 0만 가능하다. 첫 항목을 0에 고정하면 하나가 남는다. 위 함수는 기존 배정을 바꾸는 증가 경로로 둘 다 배정한다. 이 결과가 비용·경로·대기 시간까지 최적이라는 뜻은 아니다.

### 작은 정확해도 부분 배정일 수 있다

```python
from examples.methods.allocation import exact_capacitated_assignment

result = exact_capacitated_assignment([[1], [2]], [1])
assert result["status"] == "optimal"
assert result["assignment"] == [0, None]
assert result["complete"] is False
```

`optimal`은 이 작은 모델의 사전식 목표를 끝까지 계산했다는 뜻이다. 전원 처리가 필수인 서비스에서는 위 결과를 완료로 적용할 수 없다. 이 모델의 용량 총합 등 확인된 모순과, 제한된 후보 때문에 빠진 가능성을 구분한다. 예외·복구는 실제 요구와 사용자 정책의 승인 범위를 따라 적용하고 전체 결과를 다시 검사한다.

조합이 한도를 넘으면 `status="skipped"`, `assignment=None`, `objective=None`이므로 품질·불가능성 결론을 제공하지 않는다. 한도 판정은 `product`를 실행하기 전에 수행한다. 비용이 같을 때는 자원 인덱스 오름차순, 미배정은 마지막인 열거 순서의 첫 결과를 유지한다.

### 방향이 있는 경로의 뒤집기

구간을 뒤집으면 양 끝 연결뿐 아니라 내부 이동 방향도 바뀐다. `improve_tour`는 대칭 거리용 두 간선 차감 공식을 쓰지 않고 후보 순회의 전체 방향별 비용을 다시 합산한다. 비용이 엄격히 줄어드는 경우에만 채택한다.

`stop_reason="local_optimum"`은 이웃 후보인 구간 뒤집기로 더 좋아지는 해가 없다는 뜻이다. 전체 최적성을 증명하지 않으며, 방문 순서 외 조건을 만족시키는 경로 생성기도 아니다. `evaluation_limit`이면 예산까지 확인한 가장 최근 개선본을 반환한다. 실제 경로 모델의 용량·시간 조건은 해당 모델을 반영한 후보 생성과 검산에 추가해야 한다.

## 독립 검사에 사용한 관점

[테스트](../../tests/test_method_examples.py)는 다음처럼 구현과 다른 방식으로 작은 정답·불변량을 확인한다. 고정 시드를 사용하며, 대규모 성능이나 모든 입력에 대한 증명을 대신하지 않는다.

- 최단경로: 작은 그래프의 단순 경로를 전수 열거해 거리 비교. 0 비용 사이클·평행 간선·도달 불가 검사.
- 위상 정렬: 모든 순열 중 유효한 순서와 비교. 사이클·자기 연결은 거절 확인.
- 연결 숲: 작은 그래프의 간선 부분집합을 직접 검사해 최저 연결 비용 비교. 불연결·음수·자기 연결 검사.
- 구간·배낭: 가능한 부분집합을 열거해 최대 가치와 실제 선택 항목 비교.
- Fenwick·창 최댓값: 직접 배열 합·슬라이스 최대와 비교하며 상태 갱신 검사.
- 매칭: 작은 배정 조합 열거와 비교. 최대 유량: 모든 시작/종료 분리 컷과 비교하고 간선 용량·중간 정점 흐름 보존을 검사.
- 정확 배정: 자원별 누적 부하를 상태로 둔 별도 DP와 비교. 완전 탐색 한도 초과 시 열거 함수가 호출되지 않는지도 확인.
- 순회 개선: 방문 집합·시작점 보존, 전체 방향 비용, 비악화, 국소 종료 조건과 예산을 검사.

## 실제 서비스에 연결할 때

입력 파일·운영 설정에서 만든 현재 값으로 함수를 호출하고, 반환한 인덱스를 원본 ID로 되돌린다. 함수 결과에는 실제 입력·설정·정책 버전을 연결한다. 비교 실험과 재계산 API가 같은 계산 함수를 사용하게 하고, 채택 후 화면·저장·내보내기까지 검증한다. 기존 설정에서 얻은 정답이 새 정원·시간·허용 연결에서도 유효하다고 가정하지 않는다.

여기에는 웹 요청 중복 방지, 사용자 권한, 저장 원자성, 날짜·시간대 해석, 정책 예외 선정이 구현돼 있지 않다. 해당 동작은 애플리케이션 책임이며 실제 요구에 맞춰 별도로 확인한다. 알고리즘 내부의 배열 경계 검사만으로 이 기능들이 검증됐다고 보고하지 않는다.

## 확인한 원자료

직접 작성한 예제이며 아래 구현 코드를 복제하지 않았다. 외부 API의 사용 의미와 알고리즘 이름·특성을 확인하는 데 활용한 자료다. 실제 사용한 패키지·버전과 추가 자료는 작업 기록에 별도로 남긴다.

- [Python heapq](https://docs.python.org/3/library/heapq.html): 최소 힙 API와 비교 방식.
- [Python bisect](https://docs.python.org/3/library/bisect.html): 경계 위치와 좌우 삽입 기준.
- [Python collections](https://docs.python.org/3/library/collections.html#collections.deque): 양쪽 끝 큐 연산.
- [NetworkX Edmonds–Karp](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.flow.edmonds_karp.html): 단일 흐름·잔여망·복잡도 참고. 이 예제는 NetworkX를 호출하지 않으며 입력·출력 계약도 별도다.
