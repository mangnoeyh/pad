# 두 트랙 연결 연습

허용된 연습 작업 공간에서 [배정 예제](ALLOCATION_LAB.md)를 사용한다. 실제 자료나 답변을 공개 키트에 넣지 않는다. 이 연습의 목적은 후보의 점수뿐 아니라 판단·워커 전달·검증·설명이 이어지는지 확인하는 것이다. 실제 작업에서는 해당 과제의 환경·요구·시간을 우선한다.

## 시작 요청

```text
이 키트의 두 트랙 흐름을 작은 합성 배정 문제로 연습하자.
examples/ALLOCATION_LAB.md와 합성 입력을 읽고 문제를 먼저 설명해줘.
내 이해 확인 뒤, 실제 가능한 워커에게 입력→후보 저장→독립 검사 경로를 맡겨줘.
메인은 첫 결과에서 미처리·조건 충돌·비용의 의미를 설명하고 중요한 선택만 하나씩 함께 보자.
예산 안에서 현재 설정을 바꾼 재계산, 이전 후보의 잘못된 재사용 거절, 짧은 근거 요약까지 연결해줘.
실제 워커 진행과 모의 대화·설계상 예상·실행하지 않은 검사를 구분해줘.
```

## 관찰할 흐름

| 시점 | 메인·사용자의 일 | 워커의 일 | 확인할 근거 |
| --- | --- | --- | --- |
| 문제 이해 | 한 작업이 자원 하나를 선택하는 구조와 목표 순서를 이해 | 허용된 읽기·실행 기능 점검 | 실제 답변, 도구 지원 범위 |
| 첫 경로 | 미정 업무 선택이 없는 최소 범위를 위임 | 기존 명령으로 입력 읽기→후보 저장→검사 연결 | 저장 파일과 검사 결과 |
| 첫 결과 | 미배정 원인과 비용의 분모를 확인, 필요한 질문만 준비 | 확정된 범위의 검증·출력 작업 계속 | 후보별 처리 수·비용·위반 |
| 방법 비교 | 선택 순서가 결과에 미치는 영향 설명 | 두 후보를 같은 입력과 검사기로 비교 | 같은 해시·목표 순서·독립 결과 |
| 설정 변경 | 이미 허용된 정원 입력의 새 값을 전달 | 새 설정으로 재계산하고 새 결과를 검증 | 변경값이 든 입력·후보·검사 |
| 실패·부족 | 입력 오류와 유효한 부분 결과를 구분 | 잘못된 후보·오래된 입력 대응을 검사 | 거절 사유·보존된 기존 파일 |
| 이해·마무리 | 실제 입력 한 건과 핵심 판단을 자기 말로 설명 | 최종 저장본 근거를 짧게 정리 | 전체 해설 첫 요약·실제 검사 링크 |

워커에게 전달할 때는 [후보 비교 양식](../templates/candidate-comparison.md)의 입력·설정·계약 버전과 필요한 항목을 함께 준다. 새 결정에 영향받는 작업만 조정한다. 대화가 전달됐다고 가정하지 말고 실제 수신·반영을 확인한다. 답변 대기 중 진행을 관측하지 못하면 미확인으로 둔다. 모의 사용자·담당자 답변으로 연습할 때는 그 사실을 명시하고 실제 사용자의 동의나 이해로 기록하지 않는다.

## 결과를 읽는 순서

먼저 전원 처리 여부와 조건 위반을 보고, 같은 처리 범위에서 비용을 비교한다. 부분 결과는 보존해서 원인을 찾되 전원 처리로 표시하지 않는다. 이 예제에서 설정 변경은 허용된 정원 값의 변경이며, 금지 연결을 몰래 허용하는 변경과 다르다. 실제 과제의 사용자 정책 완화·예외는 출처·권한·적용 범위가 확인된 경우에만 따로 검토한다.

기존 구현을 별도 서비스로 연결하는 연습이라면 같은 계산 경로가 현재 설정을 받는지 확인한다. 웹을 실제로 만들거나 관측하지 않았다면 UI·동시 요청·저장 경합 검증은 미실행이다. 실제 서비스에서는 [웹 상태 점검](../.agents/skills/double-loop-solver/references/web-state-checks.md)의 관련 사례로 확장하고, 화면에서 현재 조건·실행 중 조건·적용 결과·실패 후 다음 행동을 구별할 수 있는지도 확인한다.

마지막에는 [전체 해설](../templates/solution-review.md) 첫 요약을 짧게 완성하고, 입력 한 건·방법 변경 이유·현재 설정·실제로 확인한 한계로 설명한다. 보고서가 있다는 사실만으로 사용자 이해를 통과 처리하지 않는다. 도구만 실행한 연습이면 자동 경로 검증과 실제 사용자 대화가 남아 있음을 구분한다.
