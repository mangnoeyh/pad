# 내부 반복의 상세 근거

선택 템플릿. 필요한 항목만 기존 작업 기록에 이어 쓴다. **누적 개선 표는 [전체 해설의 회차 이력](solution-review.md#개선-회차별-이력) 한 곳에만** 유지하고 이 상세 근거를 해당 행에서 링크한다. 현재 상태·계속/종료는 [회차 운영](../.agents/skills/double-loop-solver/references/improvement-rounds.md)을 따른다.

## 반복

- 계약·입력/설정/정책 버전 / 회차 ID와 누적 표 위치:
- 실제 문제·발견 주체와 근거 / 원인 가설:
- 하나의 논리적 변경 / 관련 파일 / 변경 전 후보:

| 검사·관찰 | 기대 결과와 근거 | 변경 전 → 후 실제 결과 | 명령·증거 경로·대상 버전 | 필수 조건·회귀·미검증 범위 |
| --- | --- | --- | --- | --- |
| | | | | |

- 미실행 검사와 이유 / 부작용·남은 한계:
- 채택·폐기·추가 확인·외부 판단의 이유 / 다음 한 작업:
- 제안·측정·구현·검증·실제 서비스 적용 중 확인한 상태:
- 관련 실제 결정·출처와 재검증 / 담당자 질문·다음 실험의 기록 위치:

## 기준본 연결

- 보존한 소스·버전·실행·입력/설정·결과·전달물의 연결 / 복구 방법:
- 필수 조건을 확인한 증거 / 미검증·실험 전용·실제 적용·전달의 구분:

통과 후보가 아직 없으면 실행 가능한 상태와 유효한 안정본을 구분한다. 계약이 바뀌면 종전 후보를 새 기준으로 재검증한다. 실제 답·실행 증거는 보존하고 현재 상태의 사본이나 두 번째 누적 표는 만들지 않는다.
