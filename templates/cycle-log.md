# 내부 반복 기록

선택 템플릿. 같은 계약의 반복은 한 문서에 이어 써도 된다. 실제로 실행한 일과 증거만 남긴다.

## 반복

- 계약 ID / 반복 ID:
- 해결할 한 문제와 가설:
- 하나의 논리적 변경 / 관련 파일:
- 변경 전 후보·안정본 참조:

| 검사·관찰 | 변경 전 실제 결과 | 변경 후 실제 결과 | 증거 경로·명령 | 필수 조건 / 회귀 여부 |
| --- | --- | --- | --- | --- |
| | | | | |

- 실행하지 못한 검사와 이유:
- 필수 조건 상태: 통과 / 실패 / 미검증
- 회귀 여부와 영향:
- 선택 지표 변화(동일 계약·동일 비교 조건에서만):
- 판정: 채택 / 폐기 / 추가 확인 / 외부 판단 요청
- 판정 이유와 다음 한 작업:
- 발견 주체와 근거: 메인 / 구현 워커 / 별도 검토 / 사용자·담당자. 제안·측정·구현·검증·서비스 적용 중 실제 상태:
- 사용자에게 보여준 회차 결과·다음 추천 / 계속·개선 종료 질문 / 실제 답변·출처 / 미응답이면 대기:

## 아직 살펴볼 것

기존 기록에 합쳐 필요한 행만 유지한다. 첫 결과와 각 회차에서 중요한 미검토 관점, 합의한 목표의 남은 여지, 새 결과로 다시 열린 질문을 갱신한다. 모든 관점을 의무적으로 조사하거나 새 문서를 만들지 않는다.

| 관련 관점·목표 | 관찰·현재 값과 근거 | 상태·아직 모르는 것 | 다음 질문/실험과 판별 조건·담당 | 답·적용·검증 결과 |
| --- | --- | --- | --- | --- |
| | | | | |

업무 사실은 담당자 질문, 위임되지 않은 절충은 사용자 결정, 구현 원인·후보 비교는 기술 실험으로 구분한다. 목표별로 현재 최선·낙관적 한계·증명된 최적을 혼동하지 않는다. 합의한 우선순위·절충 기준과 보호 조건을 적고, 엄격한 순서의 하위 개선이면 보존할 상위 값도 적는다. 관찰한 불편이 아직 승인되지 않은 강제 조건으로 바뀌지 않게 한다. 회차 종료 때에는 이 표에서 가치 있는 다음 작업 하나를 추천한다.

## 누적 개선 요약

기존 기록에 회차별 한 행씩 이어 쓴다. 종료 지시 뒤 이 표를 최종 해설과 대화에 함께 보여준다. 실패·변화 없음·폐기한 시도도 포함하며, 실제로 하지 않은 회차나 수치를 만들지 않는다. 모든 워커나 명령 하나를 별도 개선 회차로 세지 않는다.

| 회차·기준 버전 / 입력·설정 | 발견한 문제·변경 유형과 시도 | 전후 핵심 수치·필수 조건 | 부작용·한계 | 채택/보류/폐기·실제 서비스 반영 | 검증 근거 | 사용자 계속/종료 답 |
| --- | --- | --- | --- | --- | --- | --- |
| | | | | | | |

같은 기준·입력·설정에서 비교한 수치만 전후 개선으로 읽는다. 정책 변경, 알고리즘 변경, 기능·오류 수정은 구분하고 기준이 바뀌면 해당 조건에서 기준본을 다시 계산한다. 실행하지 못한 비교는 미실행으로 표시한다. 학습 초안에 영향을 주는 구조·데이터 처리·정책 변경도 해당 설명에 반영한다.

## 최선의 안정본

- 현재 계약 ID:
- 실제 스냅샷·버전·파일 위치:
- 보존 방법 / 복구 방법:
- 같은 후보를 가리키는 소스·빌드/실행·입력/설정·결과·전달물의 연결과 확인 범위:
- 실험 전용 / 현재 조건에서 검증됨 / 실제 적용됨 / 전달됨의 구분:
- 필수 조건을 확인한 검사·증거:
- 이전 안정본 대비 개선·남은 한계:

필수 조건을 실패하거나 아직 검증하지 못한 후보를 통과한 안정본으로 기록하지 않는다. 통과한 후보가 아직 없으면 그 사실과 마지막 실행 가능한 상태를 구분해 적는다. 계약이 바뀌면 종전 안정본을 새 기준으로 재검증하며, 이전 점수를 새 계약의 성과로 사용하지 않는다.
