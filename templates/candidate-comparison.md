# 같은 조건에서 후보 비교하기

선택 양식. 방법 선택이나 개선의 근거가 필요할 때 아래 항목을 기존 작업 기록에 통합한다. 실제 비교에 필요한 범위만 남기며 후보 수·문서 수·별도 승인 단계를 고정하지 않는다. 방법을 좁힐 때는 [문제 구조에 맞는 방법 선택](../.agents/skills/double-loop-solver/references/method-selection.md)을 참고한다.

## 공통 비교 조건

- 지원할 결정과 비교 목적:
- 입력 경로·버전 또는 해시 / 전체 대상 수·범위 / 축소 입력이면 선정 방식:
- 설정 버전·실제 적용 값 / 정책 버전·허용 예외 / 계약 ID와 근거:
- 공통 목표 정의·단위·방향 / 엄격한 우선순위 또는 허용된 가중 절충·동률 처리:
- 과제 필수 조건 / 현재 강제하는 사용자 조건 / 처리해야 할 범위:
- 실행 환경·설치 패키지와 버전 / 난수 시드가 있다면 값 / 시간·자원 한도와 측정 범위:
- 여러 방법을 조합했다면 단계별 역할·입출력 / 후보를 줄인 방식과 손실 가능성 / 공동 검증할 제약:

입력·설정·정책·계약과 목표 정의가 같은 후보끼리 우열을 판단한다. 실행 환경이나 자원 한도가 다르면 그 차이를 드러내고 품질·시간 차이의 원인을 단정하지 않는다. 서로 다른 정책은 별도 시나리오로 설명한다. 정책 변화와 방법 변화가 함께 있으면 기존 방법도 새 조건으로 재실행해 효과를 구분하거나, 분리하지 못했다고 밝힌다.

## 실제 결과와 근거

| 항목 | 기준본 | 비교 후보 |
| --- | --- | --- |
| 방법·주요 가정·지원하지 않는 결합 | | |
| 소스·빌드·실행 ID / 결과 경로·버전 | | |
| 적용한 입력·설정·정책·계약 버전 | | |
| 처리 수 / 전체 수·포함률 / 미처리 수·이유 | | |
| 과제 필수 조건 위반: 조건·건수·대상 | | |
| 현재 사용자 강제 조건 위반: 조건·건수·대상 | | |
| 승인된 정책 예외: 근거·발동 조건·적용 범위·정도 | | |
| 공통 우선순위에 따른 목표별 값·단위 | | |
| 최악의 부담·편중·경계 사례 / 새 누락과 영향받는 대상 | | |
| 실제 경과 시간·측정 구간 / 자원 사용·미측정 항목 | | |
| 종료 상태: 성공·시간 초과·오류·탐색 미해결 등 | | |
| 품질 근거: 작은 정확 해·하한/상한·gap·검사 범위 / 최적성 주장 가능 범위 | | |
| 실제 명령·로그·저장 결과 재검사 근거 링크 | | |
| 전체/일부 검증 범위 / 미검증·미확인 사항 | | |

승인된 예외와 필수 조건 위반을 합쳐 한 점수로 숨기지 않는다. 예외는 현재 정책의 발동·범위와 나머지 조건을 함께 검증한다. 미처리 대상을 제외해 좋아진 평균이나 목적값을 전체 개선으로 표현하지 않는다. 실제 측정값, 추정, 코드상 예상과 미실행을 구분하며 빈칸을 임의의 성공 수치로 채우지 않는다. 시간 초과·후보 미발견만으로 불가능성이나 최적성을 주장하지 않는다.

## 판단과 다음 작업

- 실제 차이와 원인에 대한 근거 / 아직 분리하지 못한 영향:
- 유지할 유효한 안정본 / 채택 또는 보류할 후보와 이유:
- 부분 후보를 보존한 경로 / 확인된 제약 충돌과 아직 해결하지 못한 탐색의 구분:
- 다음 회복안: 입력 보완·탐색 개선·기존 위임 범위의 정책 조정 또는 필요한 사용자 결정 / 예상 효과와 실측 결과의 구분:
- 정책 변경 시 바뀐 조건·결정 근거·새 계약 / 전체 재검증과 새 기준본:
- 사용자에게 설명한 절충·실제 선택 / 구현·적용·전달 여부와 남은 한계:

부분 후보는 유효한 안정본과 분리해 보존하고 [기준본과 전달](../.agents/skills/double-loop-solver/references/baseline-and-delivery.md)에 따라 진단·회복한다. 정책 변경만으로 검증을 대신하지 않는다. 현재 조건과 요구 범위를 전체 검증한 결과를 채택하며, 현재 유효한 해가 없다면 그 상태를 그대로 기록한다.
