# 과제 해결 해설 보고서

[대화·학습 지침](../.agents/skills/double-loop-solver/references/guided-collaboration.md#start-study-at-the-first-working-e2e)에 따라 첫 실제 E2E와 관련 핵심 검사 뒤 **학습 초안**으로 시작한다. 최적화 완료를 기다리지 말고 먼저 전체 요약·구조·대표 한 건을 제공한 뒤 같은 문서를 갱신한다. 지정 양식·경로를 우선하고 과제 환경 안에 저장한다. 경로 제약이 없으면 `work/solution-review.md`, 별도 예상 질답은 `work/practice-qa.md`를 쓴다. 공개 키트에는 완성 과제 내용을 올리지 않는다.

필요한 절만 채운다. 초기 미완료·미검증은 그대로 표시하고 없는 API·DB·저장·테스트를 만들지 않는다. 코드가 없으면 실제 분석·문서 생성 흐름에 맞춘다. 사용자의 이해·승인과 사람/AI의 행동은 실제 대화·실행 근거로만 기록한다.

## 현재 문서의 상태와 기준 버전

[회차 운영의 현재 상태 블록](../.agents/skills/double-loop-solver/references/improvement-rounds.md#현재-상태는-한-곳에서-갱신한다)을 이 문서 상단 또는 기존 작업 메모 **한 곳**에 둔다. 다른 곳에 이미 있다면 여기서는 그 위치만 링크한다. 실제 답을 받은 뒤에도 예전 ‘현재·대기’를 남겨두지 않는다. 날짜 있는 원답·실행 이력은 보존한다.

- 단일 현재 상태 블록 위치:
- 문서 상태·설명 대상 소스/실행·입력/설정/정책 버전·확인 시점:
- 초안을 전달한 실제 근거 / 안정된 설명과 변경·갱신 중인 부분:

## 한눈에 보는 근거 요약

- 누가 무엇을 해결하려고 사용하는가:
- 실제 입력·버전 → 핵심 처리 → 결과물·사용 방법:
- 선택한 접근과 이유 / 결과를 바꾼 실제 사용자 결정·정책:
- 같은 조건의 핵심 결과·검증 범위·로그 링크:
- 중요한 미완료·미검증·한계와 아래 상세 위치:

간결한 한 페이지 안팎의 복습 개요로 쓰고 아래 실제 코드·사례·기록에 연결한다. 분량을 채우거나 별도 요약 보고서를 늘리지 않는다.

## 먼저 따라 읽는 학습 경로

사용자에게 이 위치와 짧은 전체 설명을 먼저 알린다. 쉬운 말 → 한 번의 실제 사용 → 설정/예외 → 근거 순서로 안내한다. 필요한 용어만 처음 나올 때 풀이하고, 파일·함수 암기 대신 흐름과 선택 이유를 설명하게 돕는다.

1. 위 요약으로 누가 무엇을 입력해 어떤 결과를 얻는지 읽는다.
2. [대표 사례](#대표-사례로-따라가기)에서 같은 행·요청의 읽기부터 출력까지 따라간다.
3. 설정 변경과 [중요한 실패](#웹의-예외와-상태-변화)가 계산·화면·저장에 미치는 차이를 본다.
4. 궁금한 부분만 아래 파일·함수·실행 근거로 내려간다.

한 개념씩 질문·설명할 기회를 주되 반복 퀴즈를 강요하거나 읽었다고 이해를 기록하지 않는다. 변경 뒤 영향받은 부분만 갱신하고 회차 이력에 연결한다. 최종화 때는 전체 설명을 같은 최종 후보와 대조한다. 최적화와 학습의 실제 병행 여부도 관측 범위만 적는다.

## 문제와 요구사항

- 업무 상황·입력/자료·단위·필수 산출물/형식·실행 조건:
- 필수 조건, 확인된 업무 사실, 사용자 정책과 집행 방식·예외, 임시 가정·미확인:
- 발견한 운영 문제·실제 행/집계 근거 / 담당자 질의·부분 답·후속 확인·결정 기록 링크:
- 개발 중 정한 일반 정책과 실행 중 자동 판단할 범위 / 허용된 입력·설정과 지원 한계:

| 실제 요구사항·출처·적용 범위 | 구현·산출물 위치 | 실제 확인 근거 | 충족·미완료·미검증 |
| --- | --- | --- | --- |
| | | | |

세부 예외·조건 충돌은 [기준본과 전달](../.agents/skills/double-loop-solver/references/baseline-and-delivery.md)의 기록에 연결한다. 문제 필수 조건과 사용자 추가 조건의 권한을 섞지 않는다.

## 접근과 해결 방법

- 선택한 방법·실제 동작과 작은 예시 / 이 문제에 맞는 이유:
- 실제 검토한 대안·단계별 역할·가정·실패 사례 / 선택하지 않은 이유:
- 품질·처리 범위·속도·자원·구현 비용의 절충 / 동일 조건의 비교 근거:
- 초기 방법에서 바뀐 부분·실제 결정과 이유:

당시 검토하지 않은 대안은 사후 검토라고 표시한다. 준비된 예제와 실제 서비스 지원·측정도 구분한다.

## 최종 구현 구조

- 실제 형태·스택·의존성과 이유 / 실행 시작점·명령:
- 사용자 행동 또는 입력 → 처리 → 출력의 작은 흐름도:

| 핵심 파일·모듈·함수·문서 | 쉬운 역할 설명 | 입력/출력·연결 대상 | 실제 코드·자료 위치 |
| --- | --- | --- | --- |
| | | | |

요청/권한, 계산, 결과 검증, 저장, 표시 중 실제 책임 경계와 실패 담당, 그 경계를 택한 이유를 설명한다. 입력이나 계산법을 바꿀 때 영향받는 부분과 재사용 범위를 짚는다. 전체 파일 목록이나 존재하지 않는 아키텍처를 추가하지 않는다.

## 실제 데이터를 읽고 처리한 경로

대표 사례에 연결해 아래 실제 경로를 기록한다. 같은 설명을 여러 절에 복사하지 않고 링크한다.

- 입력 파일/API/DB·버전·선택 위치 / 읽는 시점·함수·라이브러리·읽기 범위·필요한 인코딩/헤더 설정:
- 자료형·날짜/숫자/상태 변환, 결측·중복·오류 검증과 거절 근거:
- 연결 키·관계, 필터/집계 전후 건수, 계산의 분모·단위:
- 핵심 계산에 전달한 값 / 메모리·캐시·디스크/DB의 실제 위치·재사용/무효화·저장 시점·재시작 뒤 유지:

민감한 값은 허용 범위에서 가리고 실제 값·예시·미확인을 구분한다.

## 대표 사례로 따라가기

한 실제 행·요청을 고르고 업무 관점의 짧은 이야기부터 시작한다. 단계마다 같은 대상의 원본·중간·출력 값을 연결한다. 화면 행동·이벤트·요청, 읽기·변환·검증·연결/선별·계산·저장·응답/표시·내보내기 중 존재하는 단계만 채운다.

| 실제 단계와 쉬운 설명 | 같은 건의 입력 → 중간/출력 값·자료형·단위 | 실행 시점·메모리/저장 위치 | 실제 파일·함수·실행 근거 |
| --- | --- | --- | --- |
| | | | |

핵심 기대값의 근거와 관측 결과를 대조한다. 사용자 화면 확인, AI 화면 관찰, HTTP 응답과 코드 검사를 구분한다.

설정이 있는 서비스는 같은 입력에서 설정 하나의 변경도 이어 추적한다: `이전 → 현재 허용 값 → 실제 계산 인자 → 자동 회복/예외 판단 → 전체 검증 → 저장/출력`. 관련 입력·설정·정책 버전, 재사용/무효화와 실패 상태를 연결한다. 개발 중 사람의 일반 기준과 실행 중 자동 선정을 구분하고 수동 명단·사람/AI 개입이 필요했다면 밝힌다.

## 검증과 개선 과정

| 실제 검사·명령·관찰 | 대상 버전·입력 | 기대 결과와 출처 | 관측 결과·증거 | 확인 범위·미검증·한계 |
| --- | --- | --- | --- | --- |
| | | | | |

실패·원인 가설·수정·회귀 확인은 [상세 반복 근거](cycle-log.md)를 링크한다. 기대값/계약 수정이 있었다면 실제 결정과 새 기준 재검증도 연결한다. 최초 발견자, 수정자와 재검증자를 구분하고 독립 검토의 발견을 구현팀의 자력 발견으로 쓰지 않는다. AI 자신감·통과 수·미실행/전부 skip·예제만 통과를 전체 정확성으로 바꾸지 않는다.

### 개선 회차별 이력

**유일한 누적 개선 표다.** 회차가 끝나면 필요한 한 행을 추가하고 상세 실행·비교 자료를 링크한다. 다른 기록의 표를 복제하지 않는다.

| 회차·상태 | 기준 계약·입력/설정·정책 | 관찰한 문제·변경 유형/내용 | 전후 핵심 수치·처리 범위·필수 위반 | 부작용·미해결·한계 | 채택/보류/폐기·이유·실제 서비스 적용 | 검증·로그·소스 근거 | 사용자 계속/종료의 실제 답·근거 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | |

실패·변화 없음·부분 결과도 포함한다. 제안·구현·검증·실제 적용을 구분하고, 실행하지 않은 회차나 수치를 만들지 않는다. 알고리즘/구현 변경과 정책/입력 변경을 분리하며 기준 변경 뒤에는 재기준화 또는 직접 비교 불가를 표시한다. 평균과 미처리·극단 사례, 필수 위반과 승인된 예외를 섞지 않는다. 계속/종료와 최종 표의 대화 제공은 [회차 운영](../.agents/skills/double-loop-solver/references/improvement-rounds.md)을 따른다.

## 웹의 예외와 상태 변화

실제 기능에 해당하는 중요한 실패·경합만 [앱 검사](../.agents/skills/double-loop-solver/references/app-checks.md)와 [웹 상태 검사](../.agents/skills/double-loop-solver/references/web-state-checks.md)에서 골라 설명한다. 웹이 아니면 해당 처리·출력 단계의 실패로 바꾼다.

| 시작 조건·행동 순서·발생 단계 | 합의한 기대 동작 | 사용자가 보는 것 | 처리·서버 동작 | 저장·보존/변경 결과 | 실행 근거·미검증 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

버튼 차단·오류 문구·코드 존재만으로 저장 무결성이나 실패 복구를 검증했다고 쓰지 않는다. 관측과 코드상 예상·해당 없음을 구분한다.

## 사람과 AI가 함께 해결한 과정

| 실제 단계·결정 | 사용자가 전달·선택·검토한 것 | AI의 제안·작성·실행 | 실제 대화·파일·로그 |
| --- | --- | --- | --- |
| | | | |

초기 E2E 해설 제공과 이후 변경분, 실제 이해 질문·답변을 연결한다. 병렬 사용 시 실제 역할·파일 소유권·확인된 모델/effort·대기 중 실행 관측 범위·결정 전달/반영·통합 검증을 근거로 남긴다. AI 작업을 사람이 직접 수행했다고 쓰지 않는다.

## 실행 방법과 최종 결과

- 환경·실제 확인 버전·재현 명령 / 필요한 서버 실행·포트·종료 방법:
- 결과물·최종 전달 파일 경로 / 사용한 공개 자료·커밋·파일·목적:
- 전달 소스 → 재구축/실행 → 실제 입력/설정·결과·화면/API·출력의 동일 후보 근거:
- 저장본·미저장 편집기·실행 서버·실험 경로의 구분 / 마지막 변경 후 재검증 범위:
- 구현·검증·실제 적용·저장/전달·플랫폼 제출 중 실제 확인 상태:

## 한계와 설명 준비

- 가장 중요한 미완료·미검증·결과 한계 / 다음에 확인할 것:
- 자기 말로 설명할 핵심 판단과 실제 근거:
- 별도 예상 질답 파일 / 아직 필요한 설명:

학습과 최종화는 [대화·학습 지침](../.agents/skills/double-loop-solver/references/guided-collaboration.md#final-explanation-and-practice)을 따른다. 실제 남은 예산에서 필수 검증·전달과 읽을 여유를 확보하며 짧으면 핵심 흐름·근거·한계를 우선한다. 이후 코드/정책 변경은 해당 설명·사례·질답과 재검증 상태에 반영한다. AI가 금지되는 후속 단계에는 답변 작성·수정·실시간 코칭을 하지 않는다.
