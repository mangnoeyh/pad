# 과제 해결 해설 보고서

실제 과제의 최종 구현·산출물·확정한 결정·실행 기록을 다시 읽고 작성한다. 과제 환경 안의 허용된 경로에 저장하며, 지정된 결과물 양식이 있으면 그 양식을 우선한다. 공개 키트에는 이 양식만 두고 실제 과제 내용과 완성 보고서는 올리지 않는다. 예상 질문과 답변은 별도 파일로 작성한다.

작성 시점의 실제 파일 상태와 검사 대상을 확인한다. 확인하지 못한 내용은 미확인·미검증으로 표시하고, 해당하지 않는 구성은 그 사실을 적는다. 코드가 없는 과제는 문서·분석 등 산출물이 생성되는 구조로 설명한다.

## 한눈에 보는 요약

- 해결해야 했던 문제와 목표:
- 최종 결과물과 사용 방법:
- 선택한 접근과 가장 중요한 이유:
- 핵심 구현 또는 처리 흐름:
- 실제 검증한 결과와 확인 범위:
- 중요한 한계·미완료 사항:

처음 읽는 사람이 전체 흐름을 이해할 수 있도록 이 요약부터 짧게 완성한다.

## 문제와 요구사항

- 업무 상황과 결과를 사용할 사람:
- 해결할 결정 또는 사용자 행동:
- 주어진 입력·자료·초기 상태와 의미·단위:
- 필수 산출물·형식·경로·실행 요구:
- 확정된 업무 기준과 실제 답변 출처:
- 처음 드러나지 않았던 운영 문제와 발견 근거, 필수 조건·개선 목표·가정의 구분:
- 질문 ID별 최초 질의 → 부분 답변 → 후속 확인 → 확정 또는 미확인 사항:
- 가정·아직 모르는 사항·범위 밖의 항목:

| 실제 요구사항과 근거 | 구현·산출물 위치 | 확인한 증거 | 충족·미완료·미검증 |
| --- | --- | --- | --- |
| | | | |

## 접근과 해결 방법

- 문제를 나눈 작업 단위와 전체 순서:
- 선택한 방법과 문제에 적합한 이유:
- 실제로 검토한 대안과 선택하지 않은 이유:
- 시간·환경·성능·복잡도에 따른 절충:
- 초기 접근에서 최종 접근으로 바뀐 부분과 근거:
- 같은 입력·기준에서 비교한 목표 지표와 보호한 조건·처리 범위·극단 사례:

당시 검토하지 않은 대안을 나중에 설명할 때는 사후 검토라고 구분한다. 실제 결정이나 대화가 없는데 있었다고 작성하지 않는다.

## 최종 구현 구조

- 구현 형태: 예를 들어 웹앱, CLI, 데이터 처리 스크립트, 노트북, 보고서 생성 흐름 중 실제 형태
- 사용 언어·프레임워크·라이브러리와 필요한 이유:
- 시작점: 실행 명령, 진입 파일·함수 또는 사용자가 여는 문서
- 핵심 구성의 연결: 입력 또는 사용자 행동 → 처리 → 결과

| 실제 파일·모듈·함수·문서 | 역할 | 입력과 출력·연결 대상 | 확인한 코드·자료 위치 |
| --- | --- | --- | --- |
| | | | |

작은 파일 트리나 흐름도가 도움이 되면 추가한다. 핵심 알고리즘·함수는 실제 코드 위치와 함께 설명하고, 필요한 짧은 코드 조각만 사용한다.

- 웹 과제인 경우: 화면·컴포넌트, 이벤트 처리, API·백엔드의 유무와 역할
- 데이터·상태: 실제 저장 위치, 생명주기, 중복·결측·오류·입력 검증 처리
- 외부 연결이나 의존성: 실제 사용한 것과 연결 조건
- 코드가 없는 과제인 경우: 입력 근거 → 분석·판단 → 최종 문서·표·그림의 생성 구조

존재하지 않는 데이터베이스·API·테스트·복잡한 아키텍처를 만들어 설명하지 않는다.

## 실제 데이터를 읽고 처리한 경로

데이터 입력이 있는 경우 실제 코드와 값으로 정리한다. 없는 단계는 해당 없음을 표시하고, 확인하지 못한 도구·함수는 추측하지 않는다.

- 입력 위치와 선택 방법: 실제 파일/API/DB, 경로를 정한 곳과 데이터 버전
- 실제 읽기 함수·라이브러리: 파일/함수 위치, 인코딩·구분자·헤더·읽기 범위 등 적용한 설정
- 자료형 변환과 검증: 문자열을 날짜·시간·숫자·상태로 바꾸는 규칙, 결측·오류 처리와 거절 근거
- 연결·선별·집계: 실제 키와 관계, 필터·중복 처리, 전후 건수와 계산의 분모·단위
- 계산·저장·노출: 읽은 값이 핵심 처리의 어느 인자로 들어가고 어디에 저장·출력되는지

실제 행/요청 하나를 `원문 값 → 파싱된 값·자료형 → 검증/선별 → 연결된 값 → 처리 결과 → 저장/출력`으로 따라간다. 민감한 값은 허용된 범위에서 가리며, 예시 값과 실제 관측을 구분한다.

## 대표 사례로 따라가기

실제 입력 또는 사용자 행동 하나를 고르고 해당 결과까지 추적한다.

1. 원본 입력·초기 상태와 위치:
2. 적용한 확정 규칙:
3. 주요 함수·처리 단계와 필요한 중간값:
4. 실제 출력·화면·산출물:
5. 기대 결과와 실제 결과를 대조한 근거:

중요한 예외나 경계 사례도 확인한 범위에서 설명한다. 웹 화면을 사용자가 직접 봤는지, HTTP 응답·코드 검사만 수행했는지 구분한다.

## 검증과 개선 과정

| 실제 검사·명령·관찰 방법 | 입력·검사 대상 버전 | 기대 결과와 근거 | 실제 결과 | 확인 범위와 남은 한계 |
| --- | --- | --- | --- | --- |
| | | | | |

- 내부 반복: 실제 실패, 원인 가설, 변경, 재검사·회귀 확인, 채택한 안정본
- 외부 판단: 목표·가정·자체 기대값을 재검토한 쟁점, 실제 결정자와 답변, 새 기준에서의 재검증
- 반복하지 않았다면 그 이유와 처음 확인한 검사 결과:
- 최종 파일 변경 후 다시 확인한 것과 재검증하지 못한 것:

통과 건수나 AI의 자신감으로 정확성을 대신하지 않는다. 실행하지 않은 검사와 관찰하지 않은 화면 동작은 미검증으로 남긴다.

## 웹의 예외와 상태 변화

웹 기능이 있을 때만 관련된 예외를 고른다. 입력 오류, 중복 클릭·동시 요청, 처리 중 조건 변경, 응답 순서 역전, 실패·재시도·새로고침, 권한과 결과 보존을 실제 기능에 맞게 설명한다. 중복/교체 정책과 입력 버전, 화면과 서버 저장의 동작을 구분한다.

| 시작 상태·조건 | 행동·요청 순서 | 합의한 기대 동작 | 실제 응답·화면·저장 결과 | 구현·검사 근거와 미검증 |
| --- | --- | --- | --- | --- |
| | | | | |

버튼 비활성화, 오류 문구 또는 처리 코드의 존재만으로 동시 실행과 저장 무결성이 검증됐다고 적지 않는다.

## 사람과 AI가 함께 해결한 과정

| 실제 단계 | 사용자가 전달·선택·검토한 것 | AI가 제안·작성·실행한 것 | 남아 있는 대화·파일·로그 근거 |
| --- | --- | --- | --- |
| | | | |

- 중요한 요청을 어떻게 구체화했는지:
- AI의 제안을 받아들이거나 바꾼 판단과 이유:
- 결과를 이해하기 위해 함께 확인한 대표 사례:
- 병렬 작업을 사용한 경우 실제 역할·파일 범위·확인된 모델/추론 수준·대기 중 실행 확인 범위·통합 검증:
- 메인과 사용자가 정한 변경을 워커에 전달한 기준 버전과 실제 반영·재검증 근거:

AI가 실행한 일을 사용자가 직접 수행했다고 표현하지 않는다. 사용자 이해·승인 여부는 실제 답변에 근거한다.

## 실행 방법과 최종 결과

- 필요한 환경·의존성과 실제 확인한 버전:
- 재현 명령 또는 문서를 읽는 순서:
- 서버가 필요한 경우 실행 명령·포트·경로와 종료 방법:
- 생성 파일·최종 산출물의 실제 경로:
- 사용한 공개 자료·커밋·파일·활용 목적:
- 로컬 검사와 별도로 확인할 저장·제출 상태:
- 이 보고서·질답이 설명하는 현재 저장본과 최종 변경 후 재검증 여부:
- 편집기 미저장 내용·실행 중 서버 버전·실제 전달 파일 목록의 확인 범위:
- 전달할 소스에서 재구축·시작한 실행인지, 실제 입력/설정·계산 결과·화면/API·출력과 같은 후보인지:
- 제안·구현·검증·실제 적용·전달 상태와, 실험 전용 경로를 구분한 근거:

## 한계와 설명 준비

- 아직 구현하지 못했거나 검증하지 못한 사항:
- 결과에 영향을 주는 가장 중요한 한계:
- 시간이 더 있다면 우선 확인할 것:
- 본인이 자기 말로 설명할 핵심 판단과 근거:
- 별도로 작성한 예상 질답 파일 위치:

보고서와 예상 질답 준비는 AI 사용이 허용되는 작업 시간에 마친다. 필수 검증·저장·제출 시간을 먼저 확보하며, 시간이 부족하면 요약·구현 구조·핵심 증거·한계 중심으로 줄인다. AI 사용이 제한된 후속 절차가 시작되면 답변 작성·수정·실시간 코칭을 중단한다.
