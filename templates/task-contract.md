기대 결과는 요구사항이나 독립된 근거에서 정한다. 검사 수나 선택 지표의 개선이 필수 조건 실패를 상쇄하지 않는다.

조건의 **출처**(문제 필수·사용자 추가·구현 가정)와 **집행 방식**(강제·기본 기준·개선 목표)을 따로 기록한다. 사용자 추가 조건은 강제 상태여도 사용자가 변경·완화·철회하거나 제한된 예외를 승인할 수 있다. 적용 입력/후보와 활성·보류·철회 상태를 표시한다. 승인된 예외는 새 기준에 포함해 검증하며, 미승인 완화나 문제 필수 미충족을 성공으로 바꾸지 않는다.

| 조건 ID·출처·근거 | 현재 집행 방식 | 기본 적용 범위 | 변경 권한·이미 위임한 조정 범위 | 상태·버전 |
| --- | --- | --- | --- | --- |
| | | | | |

- 완화 정도·허용 범위 / 활성·보류·철회 / 재편성 시 적용 대상을 다시 판단하는 방법:
- 회복 후보와 원인 진단 / 예상·개별 확인·공동 실측을 구분한 효과:
- 전체 재검증: 미처리·새 누락·다른 대상 부담·예외 건수·정도·모든 필수 조건:

질문 ID별 상태(미확인·부분 답변·확정·보류), 실제 답과 출처, 남은 질문, 영향을 받는 작업을 기존 기록에 이어 남긴다. 답변이 없는 내용을 확인된 요구로 쓰지 않는다. 보류 중인 질문은 보류로 남긴다. 요구·수용 기준이 바뀌면 새 계약 ID와 변경 이유를 남기고 기준선·최선의 안정본을 다시 평가한다.
