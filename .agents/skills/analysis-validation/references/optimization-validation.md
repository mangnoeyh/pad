# 최적화와 검증의 기준

먼저 실제 목표를 확인한다. 제공된 고정 입력에서 더 좋은 해를 찾는 작업과, 보지 못한 데이터의 결과를 예측하는 작업은 검증 기준이 다르다.

## 목표에 맞는 평가

- 고정 입력 최적화에서는 해당 전체 입력의 목적값과 모든 제약 충족 여부가 핵심이다. 예측 모델의 관행이라는 이유로 입력을 학습·검증용으로 나누지 않는다.
- 예측 작업에서는 학습·선택 과정과 분리한 홀드아웃을 유지한다. 전처리·특징 선택·튜닝의 정보 누출을 막고, 최종 평가 데이터를 반복 선택에 사용하지 않는다.
- 두 작업이 결합되어 있다면 최적화의 실행 가능성과 예측의 일반화 성능을 각각 검증한다.
- 입력·운영 설정을 바꿔 쓰는 서비스는 고정 입력 한 번의 좋은 결과만으로 완료하지 않는다. 실제 허용 범위의 의미 있는 대체 설정·입력에서 일반 정책이 자동 실행되는지 검증한다. 이를 예측 홀드아웃과 혼동하지 않는다. 필수 제약의 매개변수는 해당 실행에 적용된 값으로 검증하고, 기본값이나 이전 실행 값을 사용하지 않는다.

## 기준선과 실행 기록

- 가능하면 평가 범위를 정하기 전에 기존 방법을 전체 입력에서 한 번 실행하여 실제 경과 시간과 결과를 측정한다. 불가능하면 이유와 시간 추정의 불확실성을 기록한다.
- 입력 버전 또는 해시, 실행 설정, 난수 시드, 자원·시간 예산, 실행 환경과 측정 범위를 함께 기록한다.
- 목적값과 제약 위반을 별도로 보고한다. 제약은 문제에서 주어진 필수와 사용자 추가 조건을 분리하고, 사용자 조건의 현재 집행 방식·승인된 예외·버전을 함께 기록한다. 현재 기준에서 유효하지 않은 해의 좋은 목적값을 최종 성공으로 채택하지 않는다. 다만 유망한 부분 해는 보존하고 사용자 조건의 선택적 조정으로 회복할 여지를 검토한다.
- 비교에는 같은 입력 범위, 같은 목적값 정의와 명시된 자원 조건을 사용한다. 조건 차이가 있으면 결과 해석에 드러낸다.

## 필요한 경우에만 축소 선별

- 전체 평가 비용이 현재 예산에 부담이 될 때만 축소 입력으로 후보를 먼저 선별한다.
- 중요한 집단, 경계 사례와 제약 조건을 의도적으로 포함하고, 후보와 기준선을 같은 축소 범위에서 비교한다.
- 축소 결과는 대리 지표에 따른 근거로 표시한다. 전체 입력의 제약 충족이나 최적성을 보증하는 것으로 해석하지 않는다.
- 고정 입력 최적화의 축소 선별과 예측 작업의 홀드아웃은 목적이 다르며 서로 대체하지 않는다.

## 후보 채택과 불확실성

- 후보 채택 전 합의된 예산 안에서 실제 적용 대상 전체 입력에 대한 관련 검증을 마친다. 목적값, 제약, 실행 시간과 결과 재현에 필요한 정보를 확인한다.
- 전체 검증을 끝낼 수 없다면 후보를 잠정 결과로 표시한다. 같은 입력 버전·확정 조건에서 검증된 기존 결과가 있으면 안정본으로 유지한다. 없으면 현재 조건의 검증된 해가 없다고 밝히고 이전 버전 결과를 최신 결과처럼 채택하지 않는다. 전체 성공을 선언하지 않는다.
- 후보 집합이나 탐색 방법이 바뀌어도 유효한 기존 최선해를 보존하고 같은 기준으로 비교한다. 이전 해가 새 표현/후보 집합에서도 표현되는지와 누락된 부분을 확인한다. 기존 해의 재사용이 제한된 작업이라면 그 제한을 지키고 비교 근거로만 보존하며, 이전 해를 새 계산의 고정 조건으로 몰래 넣지 않는다.
- 시간 초과나 후보 미발견은 실행 불가능 또는 최적이라는 증거가 아니다. 최적성 주장은 별도의 증명이나 검증 가능한 경계가 있을 때만 한다.

## 사용자 조건의 예외와 회복 검증

- 미처리 원인이 확인된 조건 충돌인지, 후보 부족·탐색 미완료인지 구분한다. 실행 실패를 조건 완화 필요성이나 불가능성의 증거로 삼지 않는다.
- 문제 필수 제약을 유지하면서 사용자 추가 조건의 목표 전환·범위 축소·완화·특정 대상 예외를 검토할 수 있다. [기준본과 전달](../../double-loop-solver/references/baseline-and-delivery.md)에 따라 이미 위임된 조정 범위를 적용하거나 사용자가 영향과 대안을 보고 결정하도록 한다.
- 고정 명단 승인과 일반 규칙 승인을 구분한다. 자동 처리 정책으로 승인된 규칙이라면 새 입력·설정에서 새로 자격을 충족한 대상도 개별 승인 없이 선정하고 근거를 남긴다. 고정 명단 승인만으로 자동 선정 권한을 추정하지 않는다. 이전 예외 명단을 재사용하거나 정책을 벗어난 확대를 하지 않는다.
- 특정 대상이 포함된 묶음에 대한 예외라면 현재 실행의 대상 선정 규칙·최종 구성원·승인 범위로 적용 여부를 다시 계산한다. 재편성 전 묶음 ID를 그대로 면제하지 않는다. 대상이 빠진 묶음에는 원래 사용자 조건을 다시 적용한다.
- 전체 결과에서 개별 예외의 상호작용, 새 미처리, 기존 대상의 부담 변화, 예외 적용 건수·정도를 확인한다. 개별 가능 인원의 합계는 공동 배정 성공의 증거가 아니다. 부작용을 보고하되 승인되지 않은 새 제한을 추가하지 않는다.
- 예외 없는 기준본과 승인된 예외 후보는 같은 입력에서 비교하고, 정책 변경과 알고리즘 변경의 효과를 구분한다. 현재 정책으로 재검증하지 않은 과거 점수와 직접 우열을 선언하지 않는다.
- 승인된 예외를 포함한 새 조건과 문제 필수 제약 전체를 검증하면 정식 후보로 승격할 수 있다. 미승인 예외 또는 필수 조건 미충족 후보는 실험으로 남기며, 남은 예산 안에서 다음 회복 가능성을 판단한다.

## 입력 보존과 규칙 확인

- 제공된 원시 입력은 보존하고, 변형은 별도 사본에서 수행한다.
- 허용된 경우에만 확인된 스키마와 제약을 만족하는 합성 입력 또는 변형 사본으로 일반 규칙 준수와 입력별 하드코딩 여부를 점검한다.
- 이러한 점검은 보지 못한 실제 데이터에서의 예측 성능을 증명하지 않는다. 확인된 스키마를 깨는 임의 변형을 정상 입력 검증 근거로 삼지 않는다.

## 예산과 사용자 보고

- 현재 작업 단위의 공통 예산과 중간 확인 지점을 공유하고, 남은 비용에 따라 다음 평가 범위를 조정한다.
- 품질·실행 시간·자원 사용·신뢰도 사이의 중요한 절충은 실제 측정값을 제시하여 사용자가 결정하게 한다.
- 실험 횟수, 도구 설치, 프레임워크·모델 변경, 실행마다의 커밋 또는 고정 일정을 일률적으로 요구하지 않는다.
- 사용자에게는 후보가 기존 방법과 어떻게 다른지, 실제 목적값·제약 위반·경과 시간이 얼마인지, 전체 검증인지 대리 평가인지 간결하게 설명한다.
