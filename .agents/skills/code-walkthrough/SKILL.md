# 실제 값으로 흐름 설명하기

사용자가 작업을 자신의 말로 설명할 수 있게 돕는다. 합의한 작업 단위와 기존 이해 확인 대기를 유지하며, AI 사용이 제한되는 후속 절차에는 적용하지 않는다.

1. 원리를 한 문장으로 먼저 설명한 뒤 실제 파일·함수·명령으로 연결한다.
2. 실제 입력 하나를 골라 입력 → 처리 함수·규칙 → 중간값 → 관측된 결과 순으로 따라간다. 설명용 가상 입력이면 예시라고 밝히고 실제 실행 결과라고 표현하지 않는다.
3. 데이터 분석이면 작은 행 몇 개로 분모·단위·계산을 보여준다. 웹이면 화면 행동 → 이벤트/API → 상태·저장 → 응답·화면을 실제로 존재하는 부분만 설명한다.
4. 처음 나오는 용어는 그 자리에서 한 줄로 정의한다. 비유는 짧게 쓰고 실제 용어와 코드 위치로 돌아온다.
5. 한 번에 개념 하나를 짧게 설명한다. 기존 설명으로 충분한 부분을 반복하거나 모든 문법을 강의하지 않는다.
6. 결과가 업무에서 누구의 어떤 행동에 쓰이는지 연결한다. 확인되지 않은 업무 의미를 만들어내지 않는다.

이해 확인은 대화 흐름에 맞춰 한 번만 한다. 질문했다면 실제 답을 기다리고 예시 답변을 동시에 공개하지 않는다. 다만 사용자가 설명·예시 답을 직접 요청하면 제공할 수 있다. 의무 퀴즈, 점수 매기기, 매 결정의 이유 재진술을 강요하지 않는다. 실제 동의와 스스로 설명한 사실을 구분한다.

관찰과 핵심 코드 위치는 기존 작업 기록에 남긴다. 별도 EXPLAIN 문서를 강제로 만들지 않으며 최종 전체 해설 보고서와 별도 예상 질답의 구성은 기존 지침을 따른다. 직접 확인한 화면과 코드·HTTP 검사만 확인한 부분을 구분한다.
