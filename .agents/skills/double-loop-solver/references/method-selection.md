# 문제 구조에 맞는 방법 선택

분야별 방법을 구체적으로 찾을 때는 [넓은 방법 목차](../../../../docs/methods/INDEX.md)에서 관련 절만 읽는다. 기본 처리·그래프·DP·문자열·수치와 배정·흐름·경로·일정·공간·개선을 연결한다. 목록은 후보를 제한하는 규칙이 아니며, 자료에 설명된 방법과 실제 동봉 코드의 지원 범위는 다르다. 여러 방법이 필요하면 [단계 조합](../../../../docs/methods/composition.md), 검산과 종료 상태는 [검증 안내](../../../../docs/methods/validation.md)를 참고한다.

방법 선택이 품질·처리 범위·시간을 바꿀 때 읽는다. 실제 입력에서 무엇을 결정하는지, 목표의 순서, 필수 제약과 사용자 정책, 대상·후보·시간 구간의 규모와 상호 의존성을 먼저 짧게 설명한다. 이름이 익숙한 알고리즘부터 적용하지 않는다. 아래는 후보를 좁히는 안내이며 모든 방법을 구현하라는 목록이 아니다.

| 결정 변수와 목표·제약 | 설명 가능한 기준본 | 조건이 맞을 때 검토할 대안 | 규모·가정·지원하지 않는 결합 |
| --- | --- | --- | --- |
| 대상별 선택지 배정: 포함 범위를 지키며 합산 비용·선호 개선 | 유효한 기존 배정 또는 순서를 명시한 탐욕 배정과 제한된 재배정 | 일대일 매칭, 최소 비용 흐름 | 단위 수요·가산 비용과 네트워크 용량으로 표현되는 경우에 적합하다. 서로 다른 크기의 나눌 수 없는 수요, 그룹 조합 비용, 방문 순서까지 일반 흐름 문제로 처리할 수 있다고 가정하지 않는다. 후보 연결 수와 메모리를 확인한다. |
| 항목 선택·개수·자원 조합: 예산·용량 아래 가치 또는 비용 개선 | 실제 제약을 검사하는 탐욕 선택과 교환 | 정수계획(MILP), 제약계획(CP-SAT 등), 작은 경우의 열거 | 변수·제약·상호작용 수와 표현 가능성을 본다. 선형화·정수화의 의미를 확인하며, 제한 시간 안에 최적해가 나온다고 약속하지 않는다. |
| 연속량 배분: 선형 비용과 선형 자원 제약 | 실행 가능한 기존 배분 또는 단순 비례 배분 후 제약 확인 | 선형계획(LP) | 분할 가능한 양인지 확인한다. 연속해를 반올림하면 정수·최소 단위·용량 제약이 깨질 수 있다. |
| 방문 순서·연결 경로: 이동 비용, 도달·순서·용량·시간 조건 | 유효한 기존 경로 또는 가능한 위치에 삽입하는 구성법 | 경로 전용 솔버, 순서 교환·지역 탐색, 문제에 맞는 정수 모형 | 배정만 풀어서는 경로가 완성되지 않는다. 방향·연결망·이동 시간 자료와 근사 범위를 확인한다. 배정과 순서가 용량·시간을 함께 바꾸면 공동 검증한다. |
| 그룹 소속: 유사성·거리 또는 그룹별 목표 | 단순 분할 후 실제 조건 검사 | 군집화로 초기 후보 생성, 이후 제약을 반영한 배정·개선 | 군집화의 거리 목적은 용량·시간표·전원 처리 보장이 아니다. 중심점 수와 초기값에 따른 결과를 보되, 그룹 간 공유 자원까지 해결됐다고 하지 않는다. |
| 시작 시각·순서·자원 배치: 지연·완료 시간과 자원 충돌·선후 관계 | 가능한 시점부터 배치하고 충돌을 확인하는 일정 | 제약계획, 정수계획, 제한된 순서 개선 | 시간 구간 수·동시 자원·선후 관계가 탐색 규모를 바꾼다. 시간 이산화가 허용 범위와 해의 존재를 바꾸는지 확인한다. 배정이나 군집화 결과만으로 일정의 실행 가능성을 주장하지 않는다. |

기준본도 현재 조건을 통과해야 유효한 기준본이다. 단순 방법이 미처리를 남기면 부분 결과로 보존하고 원인을 진단한다. 확인된 제약 충돌인지 탐색 부족인지 구분하고, 입력 보완·탐색 개선·허용된 사용자 정책 조정의 작은 회복안을 비교한다. 자세한 범위와 승격 기준은 [기준본과 전달](baseline-and-delivery.md)을 따른다.

## 목표와 환경이 선택을 제한한다

- **엄격한 우선순위와 가중 절충을 구분한다.** 상위 목표를 훼손할 수 없다면 임의의 가중합으로 바꾸지 않는다. 단계별 최적화나 보상이 뒤집히지 않는다고 입증한 변환을 검토하고, 단계별 최적성을 확인하지 못했다면 그 한계를 밝힌다. 가중 절충은 단위·방향·가중치가 뜻하는 교환을 사용자 기준에 맞춘다. 필수 제약을 벌점으로 대신하지 않는다. [최적화 검증](../../analysis-validation/references/optimization-validation.md)의 기준을 함께 적용한다.
- **실제 설치 상태와 남은 시간을 본다.** 저장소 루트에서 `python tools/check_environment.py`로 환경을 확인하고, 필요한 API·솔버·버전의 실제 사용 가능 여부를 확인한다. 설치되지 않은 도구를 이미 쓸 수 있다고 가정하거나 비교를 위해 전체 프레임워크를 설치하지 않는다. 입력 준비·구현·전체 검증·통합·전달 비용까지 포함해 후보를 줄인다.
- **복잡한 방법의 이득은 실행으로 확인한다.** 실제 입력 규모, 후보 수, 결합 구조, 측정 시간과 자원을 근거로 추천한다. 방법 이름이나 작은 예시만으로 품질·속도·최적성을 주장하지 않는다. 전체 실행이 비싸면 같은 축소 범위로 먼저 선별하되 전체 결과와 구분한다. 실험 횟수나 시간 배분 비율을 고정하지 않는다.

## 비교에서 사용자 결정까지

[후보 비교 양식](../../../../templates/candidate-comparison.md)의 필요한 항목을 기존 기록에 넣는다. 같은 입력·설정·정책·계약과 목표 우선순위에서 기준본과 대안을 실행하고, 처리 범위·필수 위반·승인된 예외·목표값·극단 사례·시간·자원을 함께 본다. 정책이 바뀌면 변화의 효과를 설명하고 새 조건으로 다시 비교하며, 이를 알고리즘 개선만으로 보고하지 않는다.

사용자에게는 관측 결과, 추천 방법과 이유, 중요한 절충, 아직 필요한 업무 결정만 짧게 설명한다. 별도 서명이나 매 실행 승인을 추가하지 않고 기존 위임 범위를 따른다. 선택한 방법·가정·현재 기준과 실제 검증 근거를 구현 담당자에게 전달한다. 작은 배정 문제로 비교 과정을 연습할 때는 [배정 실습 안내](../../../../examples/ALLOCATION_LAB.md)를 사용한다. 실습 결과는 실제 과제의 성능 근거가 아니다.
