# 근거와 실제 사용에 맞춘 내용 검증

분석 보고서·정책 판정·응대문·설명·교육 자료처럼 내용 자체가 중요한 결과물일 때 필요한 부분만 쓴다. 웹에 담긴 내용에도 적용할 수 있지만, 화면 동작 검사를 대신하지 않는다. 별도 보고서·수치 점수·새 평가표를 요구하지 않으며 기존 요구·검증 기록에 근거를 연결한다. 이해 확인, 조기 학습과 개선 계속/종료는 기존 협업 절차를 따른다.

## 주장의 근거

결론을 바꿀 중요한 주장부터 `주장 → 원자료 위치·버전/시점·적용 범위 → 계산 또는 해석 → 남은 한계`를 따라간다. 자료에 적힌 사실, 계산 결과, 추론과 제안을 구분한다. 출처가 있다는 사실만으로 그 출처가 해당 주장을 뒷받침한다고 보지 않는다.

기간·대상·단위·정의가 다른 자료를 바로 비교하거나 관측된 차이를 원인으로 단정하지 않는다. 상충 자료는 적용 범위와 권위를 확인하고, 해소되지 않은 차이나 누락은 결론의 한계로 남긴다. 최신성 확인이 필요해도 허용된 자료·접근 범위 안에서 확인하며, 자료가 없다고 사실을 보충해 만들지 않는다. 표 데이터의 범위·집계·예측 검증은 [analysis-validation](../../analysis-validation/SKILL.md)에 연결하고 여기서 중복하지 않는다.

## 실제 결과에 맞춘 확인

| 결과에서 중요한 것 | 필요한 확인 |
| --- | --- |
| 분석·비교·추천 근거 | 핵심 결론을 원자료와 독립 계산 또는 반대 사례로 대조한다. 불확실한 가정을 바꾸면 판단이 달라지는지 확인하고, 계산한 차이와 실제 업무 효과를 구분한다. 기준안과 시나리오를 함께 다루면 상위 요약·권고·검토 표시도 어느 조건의 판정인지 결속한다. 두 경우의 판정이 반대인 사례에서 화면·내보내기의 숫자뿐 아니라 따로 읽히는 요약과 권고가 같은 대상을 설명하는지 확인한다. 이전 사람의 권고·검토를 보존할 때도 그 대상을 표시해 새 시나리오의 계산 권고와 섞지 않는다. |
| 정책 판정·절차·응대 | 실제 사례의 사실과 적용 시점/범위에 맞는 규칙을 연결해 판정·설명·다음 행동이 일치하는지 본다. 경계값, 정보 부족, 규칙 충돌·예외 중 관련 사례를 고른다. 미정 기준은 질문으로 남기고, 근거 없이 승인·거절이나 이관 규칙을 만들지 않는다. 요구된 사람의 심사·확인과 자동 처리의 경계를 유지한다. |
| 교육·설명·코칭 | 대상의 사전 지식과 실제 학습 목표에 맞춰 정확성·용어·난이도를 확인한다. 예시·연습·피드백이 그 목표와 연결되는지, 다른 사례에 적용할 때 드러나는 오개념이나 모호함이 있는지 본다. 실제 학습자가 없으면 내용 검토나 모의 적용까지만 확인했다고 기록한다. |

사람 검토를 후속 행동으로 남긴 결과는 실제 검토 경로에서 한 건을 따라간다. 검토 표시·판정·식별자뿐 아니라, 담당자가 판단할 **당시 원입력의 맥락·선택 내용·적용 버전·근거**를 이해할 수 있는 형태로 연결했는지 확인한다. 내부 저장이나 코드의 참조가 가능하다는 사실만으로 전달을 확인한 것으로 세지 않는다. 과거 기록에 최신 문구를 붙여 의미를 바꾸지 않으며, 없는 승인 기능이나 새 필수 심사를 만들지는 않는다.

합성 검사 자료도 검증하려는 업무 의미를 유지해야 한다. 같은 사례의 이름·ID만 바꾼 사본은 가져오기·저장·재계산을 검사하는 데 쓸 수 있지만, 그 변경만으로 독립된 증거·추가 자원·새로운 상황에서의 적용이 성립한다고 보지 않는다. 해당 구분을 정의하는 관계와 조건을 확인하고, 독립성이나 후속 행동의 실행 가능성을 주장하려면 그 조건을 만족하는 사례로 실제 경로를 확인한다. 형식·연결 검사와 업무 의미의 검증 범위를 구분해 남긴다.

기대 기준은 원문·확정 기준·원자료에서 정한다. 단순히 작성한 답에 맞춰 기준을 바꾸거나 표현이 매끄럽다는 이유로 정확성을 인정하지 않는다. 추가 자료·질문·시험을 제안할 때는 가능한 답이나 관측 결과에 따라 현재 권고를 유지·변경·보류할 조건을 짚는다. 자격·승인만 바꾸는 정보와 목표상 우열·실행 가능성을 바꾸는 정보를 구별하고, 하나를 알아도 다른 미확정 조건이 남는지 확인한다. 계산 가능한 비교 경계는 고정한 가정과 함께 보이되 새 업무 합격 기준으로 만들지 않는다. 기준 자체가 빠져 있으면 [담당자 질문](stakeholder-questions.md)의 같은 기록과 후속 질문 절차를 쓴다. 문체 교정은 이 검증과 별개다.

교육 결과물 자체의 학습 목표·연습은 사용자가 작업 내용을 설명하기 위한 해설·예상 질답과 구분한다. 어느 쪽도 실제 사람의 답이나 관찰 없이 이해·학습 효과를 입증하지 않는다. 내용 수정 뒤에는 영향받은 주장·사례·출처 연결을 다시 확인한다.
