# 요구 변경에서 기준본과 전달본까지

이 참고안은 기존 작업 메모나 양식에 필요한 판단과 근거를 남기는 데 쓴다. 별도 문서나 도구 도입을 요구하지 않는다.

## 1. 이해와 결정의 경계
- 처음에는 입력, 사용자 역할, 필수 동작, 결과물, 실행 환경을 함께 짚어 이해를 맞춘다.
- 범위·품질·데이터 처리처럼 결과를 바꾸는 중요한 선택은 사람이 결정한다. 합의한 작업 단위 안의 통상 명령마다 새 승인을 받지는 않는다.
- 요구마다 근거, 적용 입력·후보, 상태(활성/대기/철회)를 기록하고 다음 네 종류를 구분한다.
  - 권위 있는 필수 요구: 상위 규정·계약 등 준수 근거가 있는 조건. 사용자의 승인만으로 이를 덮어쓸 수 없다.
  - 추가 강제 조건: 사람이 명시적으로 채택한 추가 조건. 채택 전에는 대기 상태다.
  - 완화 가능한 목표: 더 좋은 결과를 위한 선호로, 강제 조건과 혼동하지 않는다.
  - 구현 가정: 작업을 진행하기 위한 잠정 해석으로, 확인 주체와 영향 범위를 붙인다.
- 변경 시 이전 내용과 새 내용, 적용 범위, 결정 주체를 기존 메모에 남긴다. 철회한 조건도 현재 조건으로 계산하지 않는다.

## 2. 확장 전에 가능한지 확인
- 선택적 범위 확장이나 추가 강제 조건 채택 전에 필요한 저비용 확인부터 한다.
- 해당 입력에서 실제 후보가 있는지, 전체·그룹별 용량의 상하한이 맞는지, 조건끼리 충돌하는지 확인한다. 적용되지 않는 검사는 생략한다.
- 결과를 다음처럼 구분한다.
  - 필요조건 실패: 실패한 조건과 근거가 확인되어 해당 입력·범위에서 성립할 수 없다.
  - 필요조건 통과·해 미확인: 아직 유효한 해를 찾지 못한 상태이며, 불가능 판정이 아니다.
  - 유효한 해 확보: 현재 전체 강제 조건과 요구 범위를 만족하는 결과를 검증했다.
- 시간 초과나 탐색 중단은 미해결로 남긴다. 불가능의 증거로 바꾸지 않는다.
- 추가 조건이 막히면 조건 조정·입력 보완·범위 선택에 필요한 근거를 사람이 판단할 수 있게 제시한다.

## 3. 작은 전체 경로와 재현 가능한 기준본
- 필수 입력부터 필수 결과까지 이어지는 가장 작은 전체 경로를 일찍 만든다.
- 기준본에는 다시 만들 수 있는 소스, 설정, 실행 진입점, 입력 또는 입력 계약, 결과와 검증 근거를 함께 고정한다.
- 이미 떠 있는 이전 프로세스나 데이터 저장소의 해시만으로 다시 만들 수 있다고 판단하지 않는다.
- 소스 스냅샷 → 빌드 → 실행 → 데이터·설정 → 결과·출력 → 전달물의 대응 관계를 기존 메모에 연결한다.
- 실제로 요구되는 구성요소만 다룬다. 컨테이너, 버전 관리, 데이터 저장소, 프레임워크나 새 기록 체계를 일괄 요구하지 않는다.
- 부분 구현, 조건 완화, 일부 입력만 다룬 실험 후보는 그 제한을 표시하고 기준본·전달 후보와 분리한다.
- 조건이 바뀌면 이전 기준본을 새 조건으로 다시 검증한다. 이전 검증만으로 새 강제 조건 충족을 주장하지 않는다.

## 4. 비용과 남은 작업 판단
- 입력 준비, 구현, 전체 검증, 통합, 전달 여유를 모두 포함해 비용을 다시 추정한다.
- 실제 입력 규모와 측정된 처리 시간, 수정량, 미확인 의존성, 변동 폭을 근거로 추정 범위와 불확실성을 적는다.
- 작은 입력의 빠른 실행을 전체 검증 비용으로 대신하지 않는다. 측정할 수 없는 부분은 미측정으로 표시한다.
- 실제 주어진 기한만 사용한다. 임의 기한, 고정 일정이나 시간 배분 비율을 만들지 않는다.
- 남은 자원으로 완료할 수 있는지 보고 선택적 개선을 조정하되, 필수 요구를 임의로 완화하지 않는다.

## 5. 전달 후보 승격과 실행 확인
- 승격 전 현재 활성인 모든 필수 요구와 채택한 추가 강제 조건, 요구된 범위, 사용자가 합의한 범위를 대조한다.
- 오프라인 실행 지시 등 환경 제한은 계속 지킨다. 외부 연결로 검증을 대신하지 않는다.
- 문서화된 깨끗한 시작 절차를 격리된 사본에서 실행한다. 운영 데이터 삭제로 초기 상태를 만들지 않는다.
- 적용되는 실제 흐름만 확인한다: 필수 입력, 변경, 재계산, 실패 시 기존 데이터 보존, 역할별 조회, 내보내기, 재시작.
- HTTP 응답 확인과 사람이 화면에서 수행하는 확인은 구별한다. 한쪽 결과로 다른 쪽까지 확인했다고 쓰지 않는다.
- 최종 확인은 전달할 바로 그 후보의 소스·빌드·설정·입력으로 수행하고 버전을 고정한다.
- 고정 뒤 변경하면 영향받는 근거를 재확인 필요로 표시하고 남은 자원 안에서 다시 확인한다. 미확인 항목은 전달 상태에 드러낸다.
- 사용자에게 설명하는 입력 → 처리 → 저장·표시·출력 흐름도 같은 버전에 맞춘다.
- 제안됨, 구현됨, 검증됨, 실제 환경에 적용됨, 전달됨을 각각 구분한다. 전달 위치와 실행 방법이 확인된 상태로 마무리한다.
