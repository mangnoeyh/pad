# 이해관계자 질문 정리 기준

이 문서는 질문을 정리할 필요가 있을 때 적용한다. 현재 정지 지점과 사용자가 정한 범위를 유지하며, 추가 질의 단계를 자동으로 만들지 않는다.

## 원래 질문을 유지하기

- 사용자가 제공한 질문의 목적과 확인하려는 결정을 보존한다. 표현을 다듬더라도 의미나 우선순위를 임의로 바꾸지 않는다.
- 한 문장에 여러 의도가 있으면 각각 답할 수 있는 질문으로 나눈다. 나눈 질문이 어느 원문에서 왔는지 추적 가능하게 둔다.
- 질문 수를 고정하거나 빈자리를 채우기 위해 새 질문을 만들지 않는다.
- 기술 구현에서 선택할 수 있는 사항과 현업에서 확인해야 하는 사실을 구분한다. 기술적 가정을 업무 사실로 확정하지 않는다.

## 이미 있는 답 확인하기

- 제공된 자료나 허용된 연결 자료에서 실제 답을 찾았을 때만 그 부분을 답변 완료로 처리한다.
- 답을 찾은 위치를 문서명과 절, 페이지 또는 직접 링크처럼 확인 가능한 인용으로 남긴다. 단순히 관련된 자료는 답의 근거가 아니다.
- 일부만 답이 있으면 답한 부분만 덜어 내고 나머지 의도를 질문으로 유지한다.
- 자료끼리 충돌하거나 적용 범위가 불명확하면 질문을 열어 둔다. 최근 자료라는 이유만으로 다른 근거를 조용히 버리지 않는다.
- 답이 없거나 근거가 약하면 미확인으로 표시한다. 추정 답변을 인용으로 꾸미지 않는다.

## 전달 형태

- 각 항목에는 확인할 내용, 필요한 이유, 현재 근거 또는 미확인 사항을 간단히 적는다.
- 답이 필요한 주체를 알면 표시하되, 추측으로 책임자를 정하지 않는다.
- 사용자가 제공한 질문과 별도 제안을 혼동하지 않게 한다. 새 제안이 꼭 필요하다면 선택 사항임을 밝힌다.
- 정리 요청만으로 외부 조사, 직접 연락 또는 메시지 발송을 시작하지 않는다. 그 행동은 요청된 범위에 포함된 경우에만 진행한다.
- 질문 목록이 완성되어도 현재 단계가 대기 중이면 다음 작업으로 넘어가지 않는다.

## 검토 예시

원문: “기존 저장소를 써도 되는지, 그리고 보관 기간은 얼마나 되는지 확인해 주세요.”

- 사용 제약: 기존 저장소 사용이 허용되는가? 허용된 기술 목록에서 답을 확인했다면 해당 근거와 함께 완료 처리한다.
- 업무 사실: 데이터 보관 기간은 얼마인가? 근거가 없으면 이 부분은 질문으로 남긴다.
- 보관 기간 자료가 서로 다르면 적용 데이터와 기준 시점을 함께 확인하는 질문을 유지한다.

최종 검토에서는 원래 의도가 빠지지 않았는지, 완료 처리한 모든 부분에 실제 근거가 있는지, 남은 충돌과 미확인 사항이 드러나는지 확인한다.
