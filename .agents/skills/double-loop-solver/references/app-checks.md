# 웹 동작을 작게 확인하기

기존에 합의한 작업 단위와 확인 범위를 유지한다. 이번 변경의 실제 사용 동작, 예상 응답, 다음 상태를 먼저 적고 필요한 만큼만 확인한다. 사용자가 일시정지를 요청하면 그 지점에서 멈춘다. 검사를 일정 개수로 맞추거나 새 도구를 설치할 필요는 없다.

**API가 있다면 실제 계약과 비교한다.** 허용된 로컬 개발 서버에서 응답의 상태코드·Content-Type·본문·변경 후 상태를 함께 본다. 정상 응답뿐 아니라 이번 변경과 관련된 빈 결과, 잘못된 입력, 없는 항목, 중복 요청을 골라 예상과 비교한다. 빈 목록과 서버 오류, JSON 오류와 HTML 오류 페이지를 같은 것으로 취급하지 않는다. 생성·목록·삭제 기능이 실제로 있으면 테스트용 항목을 생성하고 목록에서 확인한 뒤 삭제하고 다시 조회하는 흐름을 확인한다. 없는 기능을 가정하거나 운영 데이터를 바꾸지 않는다.

비동기 검색·필터가 실제로 있으면 이전 요청이 늦게 끝나도 최신 요청의 결과를 덮지 않는지 확인한다. 중복 제출 방지가 요구되는 상태 변경은 중복 요청 이후 상태도 검사한다. 소스 검토만으로 화면 동작까지 확인했다고 기록하지 않는다.

폼 입력, 재계산·저장 같은 상태 변경, 오래 걸리는 요청이 있으면 [웹 상태 예외 검증](web-state-checks.md)에서 관련 사례를 골라 정책·서버 상태·화면·저장 결과를 확인한다.

**계산 품질과 실제 사용 시간을 함께 본다.** 계산이 핵심인 서비스는 작은 예시의 함수 실행과 실제 제공 입력 규모의 서비스 실행을 구분한다. 실행 중인 요청 경로가 채택한 계산을 호출하는지 확인하고, 같은 입력·설정·기준에서 기준본과 품질·필수 조건·처리 범위·시간을 비교한다. 요청부터 결과 조회·필요한 저장/출력까지 걸린 시간을 확인하고, 가능하면 읽기·계산·검증·저장 시간을 나누어 병목을 찾는다. 실제 데이터의 희소 집단·극단값·경계 사례에서 누락과 품질 저하도 살핀다. 드문 정상 대상을 오류나 이상치로 간주해 조용히 제외하지 않는다. 별도 합성·확대 입력은 허용되고 규모 변화가 요구에 관련될 때만 사용하며 실측과 가정, 전체와 일부 입력, 실험 전용과 서비스 결과를 구분한다. 실제 작업 예산 안에서 검사하고, 운영 환경에 부하를 주거나 임의의 응답시간 합격선을 만들지 않는다. 화면의 진행 표시·오류 안내를 확인한 근거와 서버 시간 측정도 별도로 남긴다.

설치된 curl로 응답을 남길 수 있다. 아래 `run-new`는 예시 이름이며, 먼저 **기존에 없는 새 출력 폴더**를 만들고 사용한다. curl 출력 옵션은 기존 파일을 덮어쓸 수 있으므로 이전 결과의 경로를 재사용하지 않는다. Windows에서는 `curl.exe`, 다른 환경에서는 설치된 `curl`을 사용한다.

```powershell
curl.exe --max-time 5 --dump-header run-new/headers.txt --output run-new/body.txt --write-out "status=%{response_code} type=%{content_type}\n" http://127.0.0.1:8000/api/items
```

주소는 실제 허용된 개발 서버와 경로로 바꾼다. curl 종료코드 0만으로 HTTP 성공을 판단하지 않는다. 기본 curl은 4xx·5xx도 전송 자체가 성공하면 0으로 끝날 수 있다. `--fail-with-body`를 선택하면 오류 본문을 보존하면서 해당 응답에 종료코드 22를 주지만, 계약상 예상한 4xx는 기대된 결과일 수 있다. 시간 초과·연결 실패와 예상된 오류 응답을 구분해서 기록한다.

**화면은 사람이 허용된 미리보기에서 확인한다.** 키보드로 주요 입력·버튼에 접근하고, 포커스 표시와 입력 라벨, 오류 설명, 빈 상태가 이해되는지 본다. 소스에서는 비어 있거나 중복된 `id`, `label[for]`와 해당 컨트롤의 `id` 연결, `aria-labelledby`·`aria-describedby`의 각 ID 참조가 실제 요소를 가리키는지 확인한다. 이것만으로 전체 접근성을 보장하지 않는다. 자동 브라우저 조작 없이, 실제 화면에서 확인한 부분과 소스·HTTP로만 확인한 부분을 구분해서 남긴다.

화면에 적용되는 경우 키보드만으로 필수 입력·실행·오류 복구까지 이어지는지, 포커스가 보이는지, 대화상자를 닫은 뒤 조작 위치로 돌아오는지 사람이 확인한다. placeholder만 있는 입력과 이름 없는 아이콘 버튼을 점검하고, 좁은 화면·긴 값에서도 필수 정보와 버튼이 가려지지 않는지 본다. 표 내부의 필요한 가로 스크롤과 페이지 전체의 불필요한 넘침은 구분한다. 색만으로 오류·상태를 구별하게 하지 않으며, 이 점검으로 전체 접근성이나 미실행한 보조기술 검사를 통과했다고 말하지 않는다.

공식 근거: [curl 응답·출력·시간 제한 옵션](https://curl.se/docs/manpage.html), [W3C: 라벨과 컨트롤 연결](https://www.w3.org/WAI/WCAG22/Techniques/html/H44), [WAI-ARIA 1.2: ID 참조와 오류 처리](https://www.w3.org/TR/wai-aria-1.2/).
