# 사용자가 종료하는 개선 회차

기본 시작 요청은 **각 개선 회차의 결과를 보고 사용자가 계속·종료를 정하는 모드**다. 문제 이해 확인 뒤의 일반 E2E 구현은 자율 진행한다. 이 문서는 개발 중 개선의 종료권을 다루며, 완성 서비스의 정상 실행마다 개발자나 사용자 승인을 요구하는 규칙이 아니다. 사용자가 개선 종료까지 완전 자율로 맡긴다고 명시하면 그 범위를 기록하고 따른다.

## E2E가 연결되면 학습 자료부터

실제 입력이 처리·필요한 저장·화면/출력까지 이어지는 경로를 확인한 시점에 기존 전체 해설 문서의 초안을 작성한다. 모든 최적화와 최종 검증이 끝날 때까지 미루지 않는다. 사용자에게 지금 읽을 위치와 짧은 전체 설명을 제공하고, 최적화·검사 대기 중 구조·입출력·대표 한 건을 먼저 공부할 수 있게 한다.

초안에는 기준 소스·입력·설정·정책 버전, 실제 확인한 흐름, 아직 미완료인 부분을 표시한다. 안정적인 서비스 구조와 바뀔 수 있는 핵심 계산·정책·수치를 구분한다. 문서를 여러 벌 늘리지 않고 같은 [전체 해설](../../../../templates/solution-review.md)을 갱신한다. 이후에는 변경된 처리·판단·검증 부분을 알려주고, 개선 종료 뒤 최종 실행본에 맞춰 전체를 대조한다. 자료가 있다는 사실을 사용자 이해로 기록하지 않는다.

## 한 회차의 범위

1. **다음 문제를 스스로 찾는다.** 현재 결과의 큰 손실·미처리·극단 사례·근사·응답시간·운영상 의미를 실제 입력과 대조한다. 사용자가 '더 개선해'라고 해야 처음 탐색하지 않는다. 아래의 목표별 남은 여지와 [운영 관점 확인](stakeholder-questions.md)을 기존 기록에서 갱신하고, 아직 살피지 않은 중요한 관점도 후보로 올린다. 가장 눈에 띄는 한 지표만 계속 손보지 않는다.
2. **작게 실행한다.** 합의한 기준 안의 가설·변경·비교·검증을 한 회차로 정하고 실제 남은 자원 안에서 유한하게 실행한다. 새로운 필수 조건이나 미정 운영 절충에 의존하면 그 부분만 확인을 기다린다. 워커도 이 회차의 범위와 반환 조건을 받는다.
3. **질문 기회를 다시 본다.** 결과를 바꾸는 모호함·목표 간 충돌·숫자 기준·예외·현장 관행이 남았는지 [담당자 질문](stakeholder-questions.md)으로 검토한다. 목표가 최적이어도 관련 운영 관점이 미조사면 받는 사람의 다음 일이나 같은 성과의 다른 결과에서 비교할 사례를 찾는다. 이번 관찰로 어떤 불편·선택 기준을 확인했는지, 무엇이 가설·미확인인지 기존 기록에 연결한다. 짧은 답을 세부 정책 전체의 승인으로 확대하지 않으며, 담당자 사실 확인 문안과 사용자가 정할 선택을 구분한다.
4. **현재 결과와 다음 선택을 설명한다.** 실제 전후 지표·필수 조건·부작용·채택/보류·서비스 반영 여부·남은 문제를 짧게 보여준다. 계속 여부를 묻기 전에 사용자가 이미 읽고 있는 해설의 첫 문단에 현재 채택본·핵심 수치·아직 진행 중인 작업을 쓰고 누적 표에 이번 행을 더한다. 첫 문단뿐 아니라 본문의 현재 기본값·구현 여부와 기존 결정표의 대기/확정 상태도 대조한다. 원답·실행 증거 보존과, 그 근거로 만든 현재 상태표의 갱신은 구분한다. 현재 표의 낡은 대기·미측정 상태를 뒤의 추가 설명으로만 덮지 않는다. 과거 상태를 남길 때는 해당 절의 시작에 당시 시점을 표시하고 현재 상태에서 분리한다. 바뀐 위치를 알려주고, 변화가 없으면 현재 수치를 보존하고 시도 결과만 표에 남긴다. 다음 회차의 구체적인 진단이나 대안과 예상 비용을 제안한다.
5. **계속·종료를 묻고 실제 답을 기다린다.** 예: “이번 변경으로 …가 됐고 …는 남아 있어. 다음에는 …를 확인하는 걸 추천해. 개선을 계속할까, 여기서 마치고 최종 검증으로 넘어갈까?” 사용자의 중요한 결정은 하나씩 묻는다. 이미 끝낸 회차를 다시 승인받거나 개별 명령마다 묻는 것은 아니다.

계속하라는 답을 받으면 다음 회차를 시작한다. 답변 전에는 다음 개선 회차를 임의로 시작하지 않으며 침묵을 동의로 보지 않는다. 그동안 이미 승인된 독립 E2E 작업, 설명·문서 갱신·기존 근거 정리와 무관한 검증은 가능한 범위에서 이어간다. 실제 병렬·대기 중 진행은 관측한 범위만 설명한다.

실제 답을 받는 시점에도 같은 해설의 ‘답 대기’를 한 줄 갱신한다. 계속이면 현재 채택본의 수치는 두고 다음 실험이 진행 중이라고 적는다. 종료이면 개선 탐색이 끝났고 최종 검증 중이라고 적는다. 사용자가 그동안 읽는 문서에서 채택한 결과와 시험 중인 후보를 구분할 수 있게 한다.

큰 손실의 원인이 불분명하면 실제 사례 하나로 세 가지를 나눠 본다. 그 사례만 따로 볼 때의 최선, 나머지 선택을 현재대로 고정했을 때 가능한 결과, 주변 선택까지 바꾼 뒤 전체 조건을 통과한 대안이다. 앞의 두 값만으로 전체 최적이나 불가능을 선언하지 않는다. 마지막 단계는 기존 정책의 지표 순서대로 비교하며, 좋아진 대상과 부담이 옮겨간 대상을 같이 보여준다. 이 비교로도 결과가 갈리지 않으면 비용이 더 드는 탐색을 시작하기 전에 무엇을 더 확인할지 제안한다.

## 목표별로 남은 여지 확인하기

첫 E2E와 각 회차의 결과에서 합의한 목표 순서대로 `현재 값 / 비교 가능한 근거 / 다음 검사 / 상태`를 기존 기록에 짧게 남긴다. 상태는 `미탐색`, `유효한 개선안 있음`, `이번 탐색에서 개선 없음`, `해당 범위의 최적성 확인`, `기준 미확정`, `예산상 보류`처럼 실제 근거를 구별한다. 전체 표를 사용자에게 매번 읽히지 말고 다음 선택을 바꾸는 부분만 설명한다.

여러 입력·운영 설정을 지원하면 이 상태를 해당 조건별로 구분한다. 한 조건에서 상위 목표가 수렴했다고 다른 조건도 하위 목표 단계로 넘기지 않는다. 다음 작업을 고를 때 다른 조건에 남은 상위 손실과 현재 조건의 하위 개선을 함께 후보로 보고, 실제 운영상 중요도·근거·준비/실행/통합 비용으로 하나를 추천한다. 조건이 다른 점수를 합산하거나 새 가중치를 만들지는 않는다. 선택한 이유와 이번에 미루는 문제를 짧게 남긴다.

- **상위 목표가 좋아졌어도 뒤의 목표가 사라지지 않는다.** 엄격한 우선순위를 합의했다면, 상위 목표가 정체되거나 해당 범위에서 최적임을 확인했을 때 그 값을 유지한 채 다음 목표를 줄이는 작은 실험을 후보로 올린다. 처리 범위·품질이 같을 때 대기·비용·자원 낭비가 줄어드는지처럼 현재 정책에 맞는 비교를 한다. 하위 목표 개선은 앞선 모든 목표와 필수 조건을 보존하는지 전체 결과에서 검증한다. 상위 목표가 더 좋아진 후보는 기존 순서로 다시 비교한다. 가중 절충을 합의했다면 각 지표를 모두 고정하지 않고 합의한 비교식과 보호 조건을 적용한다.
- **현재 최선과 증명된 한계는 다르다.** 반복된 탐욕 해, 제한 탐색의 무개선, 개별 대상만 놓은 낙관적 값은 전체 최적의 증거가 아니다. 작은 정확 탐색이나 완화한 모형의 한계값을 구할 수 있으면 입력·설정·목표 순서·완화한 조건·증명 범위를 명시한다. 한계값과의 차이는 반드시 달성 가능한 개선량은 아니다. 상위 값이 미입증이면 그것을 유지하는 하위 실험도 가능하지만, 이후 상위 목표 재탐색의 여지는 남긴다.
- **관찰 지표는 자동으로 새 목적함수가 되지 않는다.** 총량과 함께 관련 대상별·집단별 부담, 긴 대기·최악 사례, 자원 사용의 분모를 필요한 범위에서 측정한다. 실제 자료에 없는 집단은 만들지 않는다. 부담 집중을 발견하면 업무 기준 확인이나 사용자 정책 선택으로 연결하고, 합의 없이 새로운 상한·가중치·공정성 제약을 강제하지 않는다.
- **다음 실험은 개선 여부를 판별할 수 있어야 한다.** 같은 입력·설정·정책에서 무엇을 바꾸고, 어떤 상위 값과 필수 조건을 지키며, 어떤 값이나 반례를 확인할지 정한다. 합의한 기준 안의 작은 순서 교환·재배치·대안 모형 비교는 기술 작업이다. 사용자에게 매번 알고리즘 선택이나 재승인을 요구하지 않는다. 새 정책이나 중요한 절충만 질문한다.

작은 이동의 정체가 반복되면 같은 계열의 한도만 늘리기 전에, 후보 누락 점검·다른 공동 이동 범위·작은 부분 문제의 정확 탐색처럼 막힌 구조를 바꾸는 대안을 [방법 선택](method-selection.md)에서 검토한다. `대상 입력/설정 → 남은 손실의 근거 → 이번에 달라질 탐색 구조 → 같은 범위의 비교 → 통합까지의 비용`을 연결한다. 새 방법 이름만 붙인 동일한 탐색이나 검증할 수 없는 복잡한 재작성은 개선 근거가 아니다. 이미 충분히 답한 업무 질문을 기술적 정체의 해결책으로 반복하지 않는다.

계속·종료를 물을 때는 **이번 변화, 남은 중요한 관점 또는 목표, 다음 실험 하나와 확인할 조건**을 연결한다. 개선 여지의 근거가 없으면 지어내지 않고 미확인·보류 이유를 설명한다. 종료 시에는 달성한 것과 남은 것, 종료 근거를 구분한다. 사용자의 종료 선택이나 예산 종료를 '더 개선할 수 없음'으로 바꾸지 않는다.

중요한 정책 질문의 답을 기다리는 중이면 학습 이해 질문과 계속/종료 질문을 한꺼번에 묶지 않는다. 현재 질문을 먼저 해결한 뒤 회차 선택을 확인한다. 답변 대기를 위해 턴을 넘기는 것은 전체 개선 완료 선언이 아니다. 마지막 질문과 대기 상태를 남겨 재개한다.

## 회차가 끝났다고 전체 작업을 끝내지 않는다

기능 구현 완료, 테스트 통과, 한 번의 개선 성공, 개선 없음, 작은 하한 도달만으로 개선 전체나 대화를 완료 처리하지 않는다. 더 유망한 시도가 없으면 그 근거·남은 불확실성을 설명하고 종료를 권고할 수 있지만 사용자의 종료 지시를 기다린다. 의미 없는 수정이나 동일한 실험을 무작정 반복하며 회차를 채우지도 않는다.

“개선 종료”, “이제 마무리하자” 등 명시적인 지시를 받으면 **개선 탐색을 종료**한다. 그 뒤 최종 후보 통합·검증·저장/전달 확인·해설 갱신·학습·별도 질답은 이어서 수행한다. “전체 작업 중단”은 모든 작업의 중단 요청으로 구분한다.

실제 마감, AI 허용 단계의 종료, 실행·권한의 실제 한계는 우선한다. 이 경우 추가 탐색을 멈추고 제한과 보존 상태·미완료를 알리며 허용된 마무리를 한다. 사용자가 개선을 끝내라고 했다고 꾸미지 않는다. 제안 시간이나 추정 시간을 실제 타이머로 만들지 않으며, 회차마다 전체 예산을 초기화하지 않는다.

결과 지표의 처리시간·대기·계획 기간과 알고리즘을 실행하는 실제 경과시간을 구분한다. 계획의 완료시간이 길다고 그 계획을 계산하거나 검증하는 데 같은 시간이 든다고 가정하지 않는다. 실험 비용은 관측한 실행시간이나 근거를 밝힌 추정으로 판단하고, 아직 측정하지 않았다면 그 한계를 표시한다.

## 누적 개선 표

[반복 기록](../../../../templates/cycle-log.md)의 요약 표를 기존 기록에 이어 쓴다. 회차를 단순 명령 수나 워커 수로 세지 않고 실제 가설·실행·판단의 단위로 구분한다. 표에는 실패·변화 없음·회귀로 폐기한 시도도 포함한다. 정책 변경 효과와 계산 방법 변경 효과를 구별하고 다른 기준의 점수를 단순한 연속 개선으로 연결하지 않는다.

각 회차에는 필요한 행을 대화에 짧게 보여준다. 사용자의 개선 종료 뒤에는 필요한 최종 통합·검증의 변경까지 반영해 전체 표를 최종 해설과 대화에 함께 제공한다. 실제 실행 증거가 없으면 수치를 채우지 않고 미실행으로 표시한다. 사용자의 계속·종료 답변도 해당 회차 기록에 남긴다.
