# 사용자가 종료하는 개선 회차

기본 START_HERE 요청은 **각 회차의 결과를 보고 사용자가 계속·종료를 정하는 모드**다. 이해 확인 뒤 필수 E2E 구현의 자율 진행과 선택적 개선의 계속·종료권은 구분한다. 이는 개발 진행 규칙이며 완성 서비스의 정상 실행마다 승인을 받으라는 뜻이 아니다. 개선 계속·종료까지 명시적으로 자율 위임했다면 그 실제 범위를 기록하고 따른다.

## 한 회차: 발견 → 실행 → 판정 → 실제 답

1. **다음 문제를 스스로 찾는다.** 첫 E2E와 각 회차 결과에서 합의한 목표의 남은 손실과 [운영 관점](stakeholder-questions.md)을 실제 입력·출력과 대조한다. 사용자 지적을 기다리거나 눈에 띄는 한 지표만 손보지 않는다. 아래 목표별 상태에서 중요한 다음 작업 하나와 판별 조건을 고른다.
2. **유한하게 실행한다.** 같은 입력·설정·정책에서 가설, 변경, 보호 조건, 비교·검증과 통합 비용을 정한다. 모든 워커가 실제 남은 공통 예산을 공유한다. 새 정책이나 미정 절충에 의존하는 부분만 실제 결정을 기다리고 합의한 기술 작업은 재승인 없이 진행한다. [기준본과 전달](baseline-and-delivery.md)에 따라 기준본을 보존하고 채택한 변경을 실제 서비스 경로에서 확인한다.
3. **판정하고 기록한다.** 실제 전후 수치·처리 범위·필수 조건·부작용·채택/보류·서비스 반영·미검증을 [해설의 단일 누적 표](../../../../templates/solution-review.md#개선-회차별-이력)에 연결한다. 실패·변화 없음·부분 결과도 남기며 명령이나 워커 수를 회차로 세지 않는다. 정책 변경과 방법 변경을 구분하고 기준이 바뀌면 재기준화하거나 직접 비교 불가를 표시한다. 수치와 실행을 만들지 않는다.
4. **기록을 맞춘 뒤 결과와 다음 선택을 설명한다.** 질문을 보내기 전에 현재 상태·해설·누적 표의 영향받은 부분을 실제로 갱신하고 다시 읽는다. 마지막 실제 답과 채택본을 대조해 낡은 ‘미답·미조사·수리 중’ 및 수치·기본값·적용 상태가 현재 설명에 남지 않았는지 확인한다. 끝의 부록이나 대화 요약만 추가한 것은 현재 문서 갱신이 아니다. 답변에는 갱신한 위치와 이번 변화, 남은 관점/목표, 추천 실험 하나·판별 조건·예상 비용을 연결한다. 새 모호함과 부분 답변은 [담당자 질문](stakeholder-questions.md)으로 좁힌다.
5. **계속·종료를 묻고 실제 답을 기다린다.** 예: “이번에는 …가 됐고 …가 남아 있어. 다음으로 …를 확인하는 걸 추천해. 계속할까, 개선을 끝내고 최종 검증으로 넘어갈까?” 중요한 정책 질문이 열려 있다면 먼저 그 답을 받는다. 학습 이해 질문과 회차 선택을 묶지 않는다.

계속이라는 실제 답 뒤에 다음 회차를 시작한다. 침묵·대기 시간·워커 완료·테스트 통과·한 번의 성공/무개선·일부 최적성은 계속이나 종료 지시가 아니다. 유망한 시도가 없으면 근거와 불확실성을 설명하고 종료를 권고하되 실제 종료 답을 기다린다. 의미 없는 수정이나 같은 실험으로 회차를 채우지 않는다. 답변을 기다리며 턴을 넘기는 것은 전체 완료 선언이 아니다.

대기 중 이미 승인된 독립 필수 E2E, 학습 초안·문서 갱신, 근거 정리, 읽기 전용 진단과 관련 검증은 계속할 수 있다. **다음 최적화 실험을 진단으로 바꾸어 부르거나 다른 워커에게 맡겨 대기를 우회하지 않는다.** 실제 실행 지속은 관측한 범위만 말한다.

## 현재 상태는 한 곳에서 갱신한다

기존 작업 메모 또는 해설 한 곳의 상단에 편집 가능한 `현재 상태` 절을 둔다. 짧은 요약과 계속 바뀌는 목표·운영 관점·미답 상태표 중 필요한 것을 그 절에 모으고, 본문이나 다른 문서에는 같은 상태표를 복제하지 않는다. 이미 흩어진 현재 표가 있다면 최신 답·실행 근거로 갱신해 이 절로 합치고 기존 위치에서는 링크한다. 날짜 있는 원답·실행 이력은 보존한다. 메모를 쓰고 있었다면 해설을 새로 만들었다고 기준 위치를 바꾸지 않는다.

`기준 계약·입력/설정/정책 / 채택본·검증 범위·핵심 수치 / 회차 상태·시험 후보 / 필요한 목표·관점 상태 / 실제 미답 질문·마지막 계속/종료 답과 근거 / 워커 소유권·실제 상태 / 해설 버전·갱신 필요 / 다음 행동`

회차 결과를 보여주기 전과 실제 답·상태 변경을 받는 즉시 갱신한다. 계속이면 채택본 수치는 유지하고 다음 작업의 실제 착수 상태를, 종료이면 개선 종료와 최종 검증 상태를 적는다. 전달만 한 지시를 실행 중으로 쓰지 않는다. 본문/결정표의 낡은 ‘현재·대기·미측정’도 대조하고 역사로 남길 절에는 당시 시점을 표시한다. 뒤의 부록만으로 현재 표를 덮지 않는다. 실제 원답·명령·실행 증거는 날짜 있는 이력/근거 링크로 보존하며 재작성하지 않는다.

재개할 때 이 블록, 최신 실제 답, 파일과 워커 상태를 대조한다. 오래된 미답을 현재 승인이나 차단으로 삼지 말고 문서에 없는 이해·동의를 만들거나 처음부터 반복하지 않는다.

## 목표별로 남은 여지

관련 입력·설정별로 `목표 / 현재 값·비교 근거 / 상태 / 다음 검사`를 위의 현재 상태 절에 유지한다. `미탐색`, `유효 개선안 있음`, `이번 탐색 무개선`, `해당 범위 최적성 확인`, `기준 미확정`, `예산상 보류`를 구분한다. 다음 선택을 바꾸는 부분만 사용자에게 설명한다.

- 엄격한 우선순위에서는 상위 값이 정체되거나 최적성이 확인돼도 그 값을 보존하는 하위 목표 개선을 후보로 올린다. 앞선 모든 목표·필수 조건은 전체 결과에서 검증한다. 상위 값이 개선되면 원래 순서로 비교하고 가중 절충이면 합의한 비교식·보호 조건을 쓴다.
- 한 입력/설정의 수렴을 다른 조건에 확대하지 않는다. 다른 조건의 상위 손실과 현재 조건의 하위 개선을 함께 보고 중요도·근거·실행/통합 비용으로 하나를 추천한다. 새 가중치나 조건 간 점수 합산을 만들지 않는다.
- 현재 최선, 낙관적 한계, 증명된 최적은 다르다. 제한 탐색 무개선이나 개별 사례 최선은 전체 최적/불가능 증거가 아니다. 한계값은 완화 조건·증명 범위를 밝히며 그 차이를 달성 가능한 개선량으로 단정하지 않는다. 상위 값이 미입증이어도 그 값을 보존하는 하위 실험은 가능하되 재탐색 여지를 남긴다.
- 큰 손실은 필요하면 실제 사례 하나의 독립 최선, 나머지를 고정한 개선, 주변 선택까지 바꿔 전체 조건을 통과한 대안을 구분한다. 이득과 옮겨간 부담을 함께 본다. 관련 집단·극단 사례·자원 분모는 [운영 관점](stakeholder-questions.md)에 따라 살피며 관찰만으로 새 강제 조건을 만들지 않는다.

작은 이동의 정체가 반복되면 한도만 늘리기 전에 [방법 선택](method-selection.md)에서 후보 누락, 다른 공동 이동, 작은 정확 부분문제 등 구조가 다른 대안을 검토한다. 남은 손실 → 달라지는 구조 → 같은 조건 비교 → 통합 비용을 연결한다. 방법 이름만 바꾼 반복이나 검증 불가한 대규모 재작성은 개선 근거가 아니다. 이미 답한 업무 질문을 기술적 정체 때문에 반복하지 않는다.

## 종료 전환과 실제 한계

“개선 종료·이제 마무리”라는 실제 답 뒤에는 선택적 탐색과 새 배정을 멈추고 관련 워커를 안전하게 마무리/중단해 현 계약의 가장 강한 검증 후보를 보존한다. 이어 최종 통합·검증·저장/전달·해설 갱신과 요청된 학습/Q&A를 수행한다. “전체 작업 중단”은 그 전체 범위를 멈춘다. 둘 중 무엇인지 불분명하면 범위를 확인한다. 사용자 종료를 ‘더 개선할 수 없음’으로 바꾸지 않는다.

첫 E2E의 [조기 학습](guided-collaboration.md#start-study-at-the-first-working-e2e)과 [독립 운영 검토](parallel-work.md#구현-설명과-독립된-작은-검토)를 놓치지 않는다. 종료 권고 전 중요한 검토 지적을 실제 검사·구체적 질문·근거 있는 보류로 처리한다. 확인된 주장이나 매 회차 전수 검사를 반복할 필요는 없다. 종료 후 필수 결함 수정/검증은 선택적 개선의 새 회차와 구분한다.

최종 통합의 필요한 수정까지 단일 누적 표에 반영하고 **해설과 대화 양쪽에** 제공한다. 대화는 간추릴 수 있지만 실패·미적용을 성공처럼 생략하지 않는다. 상세 실행은 [반복 기록](../../../../templates/cycle-log.md)으로 링크하고 별도 누적 표를 만들지 않는다.

실제 마감, AI 허용 단계 종료, 전체 중단과 실행·권한 한계는 우선한다. 영향받는 작업을 멈추고 실제 이유·보존 상태·미완료와 허용된 마무리를 알린다. 사용자 종료를 꾸미거나 제안 시간을 실제 타이머로 삼지 않는다. 워커·회차마다 예산을 초기화하지 말고 최종 검증·학습·전달 여유를 실제 잔여 안에 남긴다. 계획상 처리/대기 기간과 알고리즘의 실제 경과시간을 구분하며 비용은 관측 또는 근거 있는 추정임을 표시한다.
