# 한국어 보고서 문체 교정

Change style only. Never add, remove, or alter facts, numbers, or D#/R# references.
AI와 협업한 사실·실제 역할·검증 한계를 숨기거나 꾸미지 않는다. AI 사용이 제한되는 후속 절차에서는 답변 교정에 적용하지 않는다.

## 보고서 규약
- 지정 양식과 사용자 문체를 우선한다. 어울리면 제목은 명사형으로 짧게: "검증 결과", "남은 한계".
- 본문은 개조식(~함, ~임, ~했음) 또는 평서문(~했다) 중 하나로 문서 전체 통일.
- 한 문장에 중심 정보 하나를 담고, 길어 읽기 어려우면 나눔. 대신 문장 사이 연결(따라서, 이에, 다만)을 살려 뚝뚝 끊기지 않게 함.
- 숫자는 단위와 함께, 근거 위치 병기: "정확도 92.4% (scripts/check_acc.py)".
- 용어는 처음 나올 때 한 번 정의하고 이후 같은 말로 통일.

## 군더더기와 번역투 줄이기
- 빼기: "~하는 것이 중요합니다", "다양한", "효과적으로", "혁신적인", "종합적으로", "~를 통해", "결론적으로", 과한 강조·이모지·느낌표.
- 번역투 고치기: "~에 있어서" -> "~에서", "~를 가지다" -> "~가 있다", "~되어지다" -> "~되다", "~하는 것은 ~이다" 구조 줄이기, 불필요한 피동 줄이기.
- 3개씩 나열하는 습관, 매 문단 요약문, 빈 수식어 제거.
- 주어를 분명히: "본 팀은", "이 시스템은".

## 절차
1. 원문의 사실 목록(숫자, 고유명사, 참조)을 먼저 뽑음.
2. 문체 수정.
3. 수정본에서 사실 목록이 그대로인지 대조. 다르면 근거를 확인하고 문체 수정 때문에 달라진 부분을 복구한다. 사용자가 사실 정정을 요청한 변경을 임의로 되돌리지 않는다.

필요하면 [문서 대조 도구](../double-loop-solver/references/note-comparison.md)를 읽고 tools/compare_notes.py로 두 저장본의 숫자·단위·경계 기호·직접 인용 후보를 대조한다. 결과는 검토 후보이며 의미 보존의 증명이 아니다. 주체·부정·전제·주장 강도·참조 식별자는 사람이 별도로 확인하고, 모든 교정에 도구 실행을 강제하지 않는다.
