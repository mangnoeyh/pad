# 문제 구조로 찾는 방법 안내

개수에 상한을 두지 않고 기본 처리, 그래프, 탐색, 공간, 운영 최적화의 주요 구조를 연결한 참고자료다. 모든 가능한 기법을 망라하거나 특정 방법의 채택을 요구하는 목록은 아니다. 현재 문제의 입력·결정·목표·제약·규모에서 관련된 파일과 절만 읽는다. 목록 밖의 방법이 더 적합하면 그 근거를 설명하고 검토한다.

## 자료를 사용하는 순서

문제 이해와 사용자 확인은 기존 [시작 흐름](../../START_HERE.md)을 따른다. 알고리즘 자료를 읽는다고 그 전의 풀이 설계를 시작하거나 별도 승인을 추가하지 않는다.

이해 확인 후 메인은 다음을 짧게 정리한다: 바꿀 수 있는 선택, 반드시 지킬 조건, 개선할 값, 입력 규모, 실행 환경. 관련 절에서 단순한 기준선과 가치 있는 대안을 고르고 실제 자료에 맞는 적용 조건을 확인한다. 여러 분야가 섞이면 한 알고리즘 이름으로 덮지 말고 단계와 서로 영향을 주는 조건을 드러낸다.

중요한 운영 절충은 쉬운 예시로 사용자와 결정하고, 이미 합의한 기준 안의 구현·검사는 워커에게 위임한다. 워커에게는 알고리즘 이름만 주지 않고 현재 입력·설정·정책, 함수 입출력, 허용 파일, 완료 조건과 [비교할 근거](../../templates/candidate-comparison.md)를 전달한다. 추가 질문이 있는 동안에도 영향 없는 구현은 계속한다.

처음부터 모든 파일을 읽거나 모든 방법을 실험하지 않는다. 기본 결과·실패·병목이 새로운 구조를 드러내면 관련 자료를 추가로 읽는다. 준비 자료의 폭과 실제 작업의 계산 예산은 구분한다.

## 설명·실행 예제·실제 지원은 서로 다르다

- 이 폴더의 방법 설명은 적용 판단을 위한 것이다. 설명된 모든 방법의 코드가 동봉됐다는 뜻은 아니다.
- [표준 라이브러리 실행 예제](../../examples/methods/USAGE.md)에 구현 함수·계약·실행 명령을 명시한다. 예제의 작은 검산이 실제 입력의 성능이나 업무 적합성을 증명하지 않는다.
- 기존 [작은 배정 실습](../../examples/ALLOCATION_LAB.md)은 저장된 입력 해시와 후보의 독립 검사, 설정 변경을 연습한다. 임의의 경로·일정 문제를 해결하는 엔진이 아니다.
- 외부 라이브러리의 실제 설치 버전과 필요한 기능은 현재 환경에서 확인한다. 문서에 링크가 있다고 설치·네트워크·서비스 접근이 제공되는 것은 아니다. 선택한 방법에 필요한 의존성만 허용된 절차로 준비한다.
- 작은 정확 예제, 구현 테스트, 전체 결과 검증, 사용자의 이해는 각각 다른 근거다. 하나로 나머지를 통과 처리하지 않는다.

## 빠르게 찾기

저장소 루트에서 예를 들어 `rg -n "음수|용량|시간창|미배정|문자열|DP" docs/methods`로 관련 절을 찾을 수 있다. 함수별 계약과 실패 사례를 확인한 뒤 실제 문제에 맞춰 사용한다. 새 방법을 추가할 때도 항목 수보다 이 판단에 필요한 정보가 늘어나는지를 본다.

각 분야에 참고한 공식 문서·저자 자료를 연결했다. 일부 자료는 원문 서버 접근 제한으로 검색 색인에서 확인한 범위가 있다. 설명과 예제는 이 키트에서 작성했으며 외부 패키지·코드를 실제로 도입한다면 그 버전·경로·용도·라이선스를 별도로 기록한다.
