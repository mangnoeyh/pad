# 설명을 읽을 때 필요한 말

모든 용어를 먼저 학습할 필요는 없다. 현재 추천 이유를 이해하는 데 필요한 항목만 읽는다. 예시는 개념 설명이며 현재 자료에서 관찰한 결과가 아니다.

| 말 | 쉬운 뜻과 예 | 혼동하지 않을 것 |
| --- | --- | --- |
| 그래프·정점·간선 | 대상과 연결을 표현한 것. 장소가 정점, 이동 가능한 길이 간선일 수 있다 | 화면의 그래프 그림이나 차트와는 다른 의미일 수 있음 |
| 방향·가중치 | 갈 수 있는 방향, 그 연결을 쓸 때의 비용 | 거리가 같아도 양방향 시간은 다를 수 있음 |
| 상태 | 다음 선택에 필요한 현재 상황. 남은 용량과 처리한 작업 집합 등 | 중요한 과거 영향을 빼면 같은 상태로 합칠 수 없음 |
| DP·메모이제이션 | 같은 중간 상황의 결과를 저장해 반복 계산을 줄임 | 과거 정보를 마음대로 버리거나 모든 조합을 자동으로 싸게 푸는 방법은 아님 |
| 탐욕법 | 지금 정한 기준에서 가장 좋은 선택을 하나씩 함 | 각 선택이 좋아 보여도 전체 결과가 최선일 수는 없음 |
| 기준선 | 개선 전과 비교할 단순하고 재현 가능한 방법 | 필수 조건을 어긴 결과는 유효한 최종 기준본과 구분 |
| 후보 | 실제로 선택할 가능성을 검토하는 항목·연결·경로 | 후보에 없다는 사실이 현실에서도 불가능하다는 증거는 아님 |
| 가지치기 | 이후 볼 필요가 없는 탐색 부분을 줄임 | 수학적 근거로 제거한 것과 속도를 위해 임의로 제외한 것은 다름 |
| 결정 변수 | 프로그램이 값을 정해야 하는 선택. 누가 어느 자원을 쓸지 등 | 관리자가 입력한 고정 설정과 구분 |
| 제약 | 선택 결과가 지켜야 하는 조건 | 사용자의 선호를 원문 필수 조건으로 올리지 않음 |
| 목적함수 | 조건을 지킨 후보 중 무엇이 더 좋은지 비교하는 계산 | 필수 조건을 큰 벌점 하나로 대신하면 위반이 허용될 수 있음 |
| 가능 해·유효 해 | 현재 모형의 조건을 만족하는 결과 | 모형에서 빠진 실제 요구까지 만족한다는 뜻은 아님 |
| 최적해 | 현재 모형·목표에서 더 좋은 결과가 없다는 근거가 있는 해 | 이번에 찾은 후보 중 최고인 것, 지역 최적과 구분 |
| 정확 알고리즘 | 계약에 맞는 입력에서 정답을 구하는 방법 | 모든 크기의 입력을 제한 시간 안에 끝낸다는 뜻은 아님 |
| 휴리스틱 | 좋은 결과를 빨리 찾기 위해 선택·탐색을 줄이는 방법 | 품질 보장이 없다면 항상 최적이라고 설명하지 않음 |
| 근사 알고리즘 | 조건을 만족할 때 최적값 대비 오차·비율을 보장하는 방법을 뜻할 수 있음 | 단순 추정치나 아무 휴리스틱을 이 보장과 혼동하지 않음 |
| 지역 탐색·지역 최적 | 현재 해 주변의 작은 변경을 시험하고, 그 변경으로는 더 나아지지 않는 상태 | 더 큰 변경이나 다른 출발점에서는 좋아질 수 있음 |
| 매칭 | 서로 연결 가능한 대상을 짝지음 | 짝을 지었다고 일정·경로·복잡한 그룹 제약이 해결되지 않음 |
| 흐름·용량·컷 | 연결망을 통과시키는 양, 각 연결의 한도, 양쪽을 가르는 경계 | 개별 대상을 나눌 수 없는 조건이나 여러 종류의 흐름은 별도 모델 필요 |
| 완화 | 일부 조건을 빼거나 덜 엄격하게 만든 다른 문제 | 연구용 하한 계산과 실제 정책 완화 승인은 다름 |
| 하한·상한 | 최적값이 있을 수 있는 범위를 좁히는 값 | 최소화에서 유효 후보는 상한이고, 최대화는 방향이 바뀜 |
| gap | 현재 후보와 계산된 경계 사이의 차이 | 라이브러리의 정의·단위·방향·분모를 확인해야 함 |
| 사전식 목표 | 첫 기준을 우선하고 같은 경우에만 다음 기준 비교 | 가중합처럼 상위 손해를 하위 이득과 바꾸는 정책이 아님 |
| 파레토 후보 | 다른 후보가 모든 목표에서 같거나 더 좋고 하나 이상에서 더 좋은 경우에 지배되지 않는 후보 | 하나의 정답을 자동으로 고르는 정책은 아님 |
| 분할 정복 | 작은 독립 부분을 풀고 합치는 구조 | 공유 자원이 있는 그룹을 임의 분할해도 된다는 뜻은 아님 |
| 시간 복잡도 | 입력 크기가 커질 때 필요한 연산이 어떻게 증가하는지 표현 | 초 단위 실행시간 자체는 구현·장비·데이터에 따라 달라짐 |
| 공간 복잡도 | 입력이 커질 때 추가 저장이 어떻게 늘어나는지 표현 | Python 객체당 실제 메모리와 전체 입력 저장도 따로 고려 |
| NP-hard | 일반적인 모든 입력을 효율적으로 푸는 방법이 알려지지 않은 어려운 문제들을 포함한다는 분류 | 특정 입력을 못 풀거나 유용한 결과를 못 만든다는 뜻은 아님 |
| 검산 기준·oracle | 작은 입력의 정답이나 유효성을 독립적으로 판단할 비교 기준 | 생성기와 같은 잘못된 가정을 쓰면 같이 틀릴 수 있음 |
| 종료 상태 | 해를 찾았는지, 최적을 확인했는지, 중단됐는지 등 실행 결과의 구분 | 시간 부족으로 못 찾은 것은 불가능 증명이 아님 |

실제 설명은 [쉬운 설명과 학습](explain.md), 방법 선택은 [목차](INDEX.md), 결과의 보장 범위는 [검산](validation.md)에서 연결한다.
