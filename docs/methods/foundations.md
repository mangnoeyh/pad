# 기본 처리와 자료구조

입력을 빠르게 찾고 정렬하며 집계하는 단계에 쓴다. `n`은 원소 수, `k`는 선택할 수, `R`은 값 범위다. 아래 복잡도는 비교·해시·산술 한 번을 상수 시간으로 보는 모형이며, 긴 문자열과 큰 정수의 비용은 별도다. 실제 Python 메모리와 전체 입력·직렬화 시간도 측정한다. 이 문서는 방법 선택 자료이며 나열된 방법의 구현이 모두 저장소에 있다는 뜻은 아니다.

## 빠른 선택

| 관찰한 구조 | 먼저 검토 | 다음 후보 또는 주의 |
| --- | --- | --- |
| ID로 반복 조회·중복 확인 | 해시 맵·집합 | ID 정규화와 중복 처리 의미를 먼저 확정 |
| 순위·동률·처리 순서가 필요 | 정렬 | 동률을 입력 순서에 맡겨도 되는지 확인 |
| 다음 사건·가장 작은 비용만 반복 선택 | 힙 | 값 변경·삭제는 별도 설계 |
| 정렬된 값에서 경계 조회 | 이분 탐색 | 삽입까지 빠른 것은 아님 |
| 구간 합·개수 반복 조회 | 누적합 | 변경이 많으면 [구간 자료구조](ranges-and-time.md) |
| 연속 구간을 한 번씩 이동 | 두 포인터·슬라이딩 윈도 | 조건의 단조성이 필요 |
| 모든 쌍을 비교하느라 느림 | 인덱스·정렬 병합·후보 축소 | 후보 축소로 정답 후보를 버리지 않는지 검증 |

## F01 — 정렬과 안정된 동률 처리

- **언제:** 처리 우선순위, 날짜순 이력, 금액순 상위 목록, 이후의 병합·이분 탐색 준비.
- **방법·비용:** 비교 정렬은 보통 `O(n log n)`. Python 정렬은 같은 키의 상대 순서를 보존한다. 여러 기준은 우선순위가 드러나는 키로 표현한다. Python의 안정성·`key` 동작은 [정렬 공식 문서](https://docs.python.org/3/howto/sorting.html)에서 확인한다.
- **한계·반례:** `updated_at`만 같다는 이유로 충돌한 revision을 임의 선택하지 않는다. ID를 문자열로 두면 `"10"`과 `"2"`의 순서는 숫자순과 다르다. 동률을 깨는 규칙 자체가 업무 정책일 수 있다.
- **검산·연결:** 작은 표를 손으로 정렬해 비교하고, 같은 행 순서를 섞어도 업무상 결과가 같아야 하는지 확인한다. 원본 순서 보존이 필요한 경우 복사 정렬한다.

## F02 — 해시 맵·집합·빈도표

- **언제:** 키 조회, 중복 탐지, 빈도 집계, 같은 ID의 자료 연결. 평균적인 조회·삽입·삭제는 `O(1)`, 전체 저장은 `O(n)`이며 해시 충돌과 키 크기의 비용이 있다.
- **예시:** 자원 ID별 허용 정원을 맵으로 만들고 요청의 참조 ID를 조회한다. 중복 키가 있으면 마지막 행으로 덮어쓸지, 오류인지 먼저 정한다.
- **한계·반례:** 집합으로 바꾸면 중복 횟수와 순서가 사라진다. `None`, 빈 문자열, `"001"`, `1`을 동일 ID로 취급하면 안 되는 입력도 있다. 근사 중복 판정은 정확한 집합 membership과 다르다.
- **검산·연결:** 행 수, 고유 키 수, 중복 건수, 조인 전후 cardinality를 함께 기록한다. 정렬 후 인접 키 비교를 작은 독립 기준으로 쓸 수 있다.

## F03 — 큐·덱·스택

- **언제:** FIFO 작업, BFS, 최근 기록, 괄호·상태 복구, 반복형 DFS. 덱 양끝 삽입·삭제와 스택 끝 연산은 적절한 자료구조에서 `O(1)` 수준이다.
- **한계·반례:** Python 리스트의 앞 원소 삭제를 반복하면 전체가 `O(n²)`로 커질 수 있다. 스택의 후입선출과 큐의 선입선출은 결과 순서를 바꾼다.
- **검산·연결:** 빈 큐, 한 항목, 재시도 삽입 위치, 동일 우선순위를 확인한다. 메모리 큐는 프로세스 재시작 후 남는 영속 작업 큐를 대신하지 않는다. [collections의 deque](https://docs.python.org/3/library/collections.html#collections.deque) API를 확인한다.

## F04 — 힙과 우선순위 큐

- **언제:** 가장 이른 사건, 최소 비용 후보, 제한된 자원에서 다음 처리 항목. 힙 생성 `O(n)`, 삽입·제거 `O(log n)`, 최솟값 보기 `O(1)`.
- **예시:** `(시각, 안정된 순번, 항목 ID)`를 넣어 동시각 사건도 비교 가능하게 한다.
- **한계·반례:** 힙 내부 배열 전체가 정렬된 것은 아니다. 항목의 우선순위를 외부에서 바꾸면 힙이 자동 갱신되지 않는다. 이전 항목을 무효 표시하고 새 버전을 넣는 방식은 오래된 항목 제거와 메모리 정리가 필요하다.
- **검산·연결:** 정렬 리스트 기준과 같은 pop 순서인지 확인한다. 최신 Python 문서에 나온 최대 힙 API가 실행 환경에 있다고 가정하지 않는다. [heapq 공식 문서](https://docs.python.org/3/library/heapq.html).

## F05 — 이분 탐색과 답에 대한 이분 탐색

- **언제:** 정렬된 배열의 처음/마지막 경계 또는 단조인 판정에서 최소 가능 값. 배열 조회 `O(log n)`; 정수 범위 폭 `U`에서 답 탐색은 `O(log U × 판정비용)`.
- **조건:** 판정 `P(x)`가 한 방향으로만 참/거짓을 바꿔야 한다. 최솟값·최댓값·동률·빈 구간과 끝점 포함을 명시한다.
- **반례:** 정원이 커지면 항상 편성이 쉬워지는지 확인하지 않은 채, 별도 최소 탑승률·고정 운행 수까지 엮인 휴리스틱 성공 여부로 탐색하면 단조성이 깨질 수 있다. 휴리스틱 실패는 `불가능` 판정기가 아니다.
- **검산·연결:** 작은 범위를 전수 조사해 단조성과 반환 경계를 검산한다. `bisect`의 탐색은 로그 시간이지만 리스트 `insort`는 원소 이동 때문에 선형일 수 있다. [bisect 공식 문서](https://docs.python.org/3/library/bisect.html).

## F06 — 두 포인터·슬라이딩 윈도

- **언제:** 정렬된 두 목록 병합, 조건을 만족하는 연속 구간, 고정 길이 집계. 각 포인터가 뒤로 가지 않고 각 원소가 제한 횟수 처리되면 `O(n)` 또는 두 목록 길이 합의 시간.
- **반례:** 합이 목표보다 크면 왼쪽을 줄이는 비음수 구간 알고리즘은 음수가 섞이면 성립하지 않는다. 시간순 이벤트라도 늦게 도착한 사건이 허용되면 단순 전진 창을 재검토한다.
- **검산·연결:** 모든 짧은 부분 구간을 열거한 결과와 비교한다. 윈도 경계 시각, 최대값·최소값의 동률, 빈 구간을 포함한다.

## F07 — 누적합·차분 배열

- **언제:** 변경 없는 배열의 구간 합·개수, 여러 구간에 더한 뒤 마지막 결과 한 번 생성. 누적합 구성 `O(n)`, 반열린 구간 `[l,r)` 합 `O(1)`; 차분 구간 갱신 `O(1)`, 최종 복원 `O(n)`.
- **확장:** 2차원 누적합은 직사각형 조회를 빠르게 하지만 격자 전체의 메모리 `O(HW)`가 필요하다. 평균은 합뿐 아니라 유효 개수도 같이 누적한다.
- **반례:** 누적 평균을 다시 평균내면 표본 수가 다른 구간에서 틀린다. 중간 결과를 계속 조회해야 하는 동적 갱신에 단순 차분만 두면 오래된 값이 보인다.
- **검산·연결:** 원본 직접 합산과 비교하고, 모든 경계·빈 구간·전 구간·음수·큰 정수를 검사한다. 갱신이 잦으면 Fenwick/segment tree를 검토한다.

## F08 — 단조 스택·단조 덱

- **언제:** 다음 큰 값, 가격·부하의 경계, 이동 구간의 최대·최소. 각 원소를 넣고 빼는 횟수가 제한되므로 전체 `O(n)`.
- **조건:** 제거된 후보가 앞으로도 유리해지지 않음을 설명할 수 있어야 한다. 값만 저장하지 말고 만료를 판단할 위치도 보존한다.
- **반례:** `<`와 `<=`를 바꾸면 같은 값의 대표 위치가 달라진다. 최신 값 우선과 최초 값 우선이 다르다.
- **검산·연결:** 모든 값 같음, 증가·감소·교대, 창 크기 1·전체 길이를 직접 탐색 기준과 비교한다.

## F09 — 좌표 압축

- **언제:** 값은 크고 드물지만 순서·동일성만 필요한 Fenwick·segment tree·오프라인 처리. 정렬로 `O(n log n)`, 변환 저장 `O(n)`.
- **한계·반례:** `100, 101, 100000`을 `0,1,2`로 바꿔도 실제 거리나 시간 차이가 보존되는 것은 아니다. 새 값이 들어오면 기존 압축표와 인덱스가 바뀔 수 있다.
- **검산·연결:** 역변환 표를 보존하고, 순서·중복만 보존되는지 확인한다. 면적·시간 길이는 원래 좌표 차이를 사용한다.

## F10 — 상위 k개·선택·스트리밍

- **언제:** 전체 정렬 없이 작은 상위 목록 유지. 크기 `k` 힙은 `O(n log k)` 시간과 `O(k)` 보조 공간. quickselect는 흔한 무작위 구현에서 평균 `O(n)`, 최악 `O(n²)`이며 결과 전체는 정렬되지 않는다.
- **한계·반례:** k번째 값과 동률인 항목을 모두 포함하라는 요구는 정확히 k개 반환과 다르다. 근사 스트리밍 빈도·샘플링은 정확한 상위 목록을 보장하지 않는다.
- **검산·연결:** 전체 정렬과 비교하고 `k=0`, `k>n`, 전체 동률의 정책을 확인한다. 입력 일부만 본 상태를 전체 데이터 상위 순위로 표시하지 않는다.

## F11 — 정렬 병합·인덱스 조인

- **언제:** 두 정렬된 자료의 시간·키 연결, 범위 후보 생성. 이미 정렬됐다면 병합은 `O(n+m+출력수)`; 정렬 비용은 별도.
- **반례:** 양쪽에 같은 키가 여러 개면 출력이 곱으로 증가한다. 가장 가까운 과거 시점 조인에 미래 행을 연결하면 시간 의미가 바뀐다.
- **검산·연결:** 작은 중첩 반복 기준과 비교한다. 일대일/다대일/다대다 허용 여부, 미연결 행 처리, 경계 시각과 타임존을 먼저 확정한다. 이는 데이터 구조 선택인 동시에 자료 의미 문제다.

## F12 — 비트셋·불리언 상태 압축

- **언제:** 제한된 정수 ID의 집합 교집합·합집합, 가능한 합 상태, 대량 이진 표식. `W`비트 집합 연산은 기계어 수에 비례하며 Python 큰 정수도 길이가 커지면 비용이 증가한다.
- **한계·반례:** `1 << 거대한_ID`는 적은 행에서도 큰 메모리를 쓸 수 있다. 이진 표식은 개수나 대상의 출처를 보존하지 않는다.
- **검산·연결:** 일반 set/불리언 배열과 비교하고, 실제 ID↔비트 위치 표를 버전과 함께 유지한다. 상태 수가 폭발하는 문제를 비트연산만으로 해결했다고 하지 않는다.

## F13 — Counting sort·radix sort

- **적용:** 값이 제한된 정수 범위이거나 고정 폭 자리로 표현될 때 비교를 줄이는 정렬. counting sort는 `O(n+R)` 시간과 범위에 비례한 저장, `d`자리·자리 범위 `B`인 radix는 일반적으로 `O(d(n+B))`.
- **조건:** 음수·고정소수·문자열의 인코딩과 정렬 의미를 일치시킨다. LSD radix의 각 자리 정렬은 안정성이 필요하다.
- **반례:** 원소가 몇 개라도 최대 ID가 매우 크면 counting 배열이 낭비된다. 문자 코드순과 사람이 기대하는 언어 정렬은 다를 수 있다.
- **검산:** 비교 정렬 기준과 같은 순서·안정성인지 확인한다. Python에서는 메모리·인터프리터 반복 비용 때문에 이론상 선형인 직접 코드가 내장 정렬보다 느릴 수 있어 실측한다.

## F14 — Reservoir sampling·근사 집계

- **적용:** 길이를 미리 모르는 스트림의 균등 표본 `k`개는 reservoir sampling으로 `O(n)` 처리·`O(k)` 저장이 가능하다. 거대한 집합의 대략적인 크기나 빈도는 별도의 확률적 스케치를 검토한다.
- **조건:** 표본의 포함확률·seed·관측 범위를 남긴다. Bloom filter처럼 오탐을 허용하는 membership은 정확한 집합 조회와 구별한다.
- **반례:** 앞부분 k개 읽기는 균등 표본이 아니다. 근사 필터의 양성 판정만으로 중복이라고 삭제하면 정상 항목을 버릴 수 있다.
- **검산·연결:** 작은 알려진 모집단에서 여러 seed의 포함빈도를 관찰하고, 정확 계산과 근사 오차를 비교한다. 통계적 관찰은 완전한 분포 증명이 아니며 최종 필수 대상 목록은 정확하게 유지한다.

## 대화와 적용

일반 자료구조 선택은 메인이 이유를 알려주고 진행한다. 동률 처리·자료 삭제·늦은 데이터 처리처럼 결과 의미가 달라질 때만 중요한 기준을 묻는다. 예: “같은 우선순위라면 먼저 접수한 요청을 먼저 처리하는 기준을 추천합니다. 이 기준으로 할까요?” 답을 기다리는 동안 입력 검증과 독립 화면 작업은 이어갈 수 있다.

공통 API 사용법은 연결된 공식 문서를 확인하고 실행 환경의 버전을 따른다. 위 사용 카드의 예시·반례는 이 자료를 위해 작성했으며 외부 구현 코드를 포함하지 않는다.
