# 개선 탐색·회복·시뮬레이션

기본 동작은 되지만 비용·부담·처리율이 아쉽거나, 설정 변화에 따라 해를 다시 만들어야 할 때 읽는다. 알고리즘을 많이 실행하는 것이 목적은 아니다. 현재 가장 큰 손실의 원인을 찾아 가치 있는 후보를 비교하고 실제 서비스에 연결한다. 이 문서의 모든 기법이 저장소에 실행 코드로 포함된 것은 아니다.

## 시작점과 결과 보존

현재 입력·설정·정책에서 검사한 유효 해를 따로 보존한다. 탐색 중인 해와 지금까지 가장 좋은 유효 해를 분리하고, 부분 결과·일시적 제약 위반이 실제 적용 결과를 덮어쓰지 않게 한다. 이전 설정의 좋은 결과는 현재 설정으로 검증하기 전에는 안전한 복구본이라고 할 수 없다.

기준선과 후보는 같은 입력·설정·정책·목표 순서에서 비교한다. 정책 완화로 가능해진 후보와 알고리즘만 바꾸어 좋아진 후보의 효과를 나누어 기록한다. 전체 대상이 필수라면 누락을 벌점으로 상쇄해 좋은 점수를 만드는 탐색 결과를 최종 적용하지 않는다.

## 작은 움직임부터 개선

### 이동·삽입·교환

대상 하나를 다른 묶음으로 옮기거나, 위치를 바꾸거나, 두 대상을 서로 바꾼다. 전체 구조를 다시 만들지 않아도 개선되는지 빠르게 확인할 수 있다. 한 번의 모든 쌍 검사에는 `O(n²)` 후보가 생기고 각 후보의 검증 비용이 추가된다. 처음 좋아진 이동을 고르는 first improvement와 전부 본 뒤 가장 좋은 이동을 고르는 best improvement는 시간·결과가 다를 수 있다.

용량·금지 연결·시간·예외 자격을 움직인 대상만이 아니라 영향받은 묶음 전체에서 확인한다. 예: 특정 대상이 떠난 묶음은 더 이상 최소 인원 예외 대상이 아닐 수 있다. 작은 예제로 변화량 계산과 처음부터 재계산한 비용이 같은지 검사한다.

### 2-opt·구간 재연결

경로의 연결 두 곳을 바꿔 순서를 개선한다. 대칭 거리에서는 두 연결의 변화로 비용 차를 쉽게 계산할 수 있지만, 비대칭 경로에서 구간을 뒤집으면 내부 모든 간선의 방향도 바뀐다. 끝의 간선 둘만 바꿔 계산하면 틀릴 수 있다. 순서 변화 뒤 시간창·체류시간·선행 관계도 다시 검사한다.

### 연쇄 재배정·ejection chain

한 대상을 넣기 위해 다른 대상을 밀어내고 그 대상을 또 다른 곳으로 옮기는 연쇄를 탐색한다. 단일 이동으로 막힌 배정을 구제할 수 있다. 깊이·후보 수가 늘면 급격히 비싸지므로 제한과 방문 상태를 기록한다. 중간에 빠진 대상을 잃지 않도록 보존하고, 연쇄 전체가 완료된 뒤 전원 여부와 중복을 검증한다.

### Variable neighborhood descent·search

단일 이동, 교환, 묶음 교환처럼 이웃 구조를 바꾸어 한 종류의 국소 최적에서 벗어나는 방법이다. 이미 검사한 후보를 반복 생성하는지, 더 큰 이웃의 비용이 이득에 맞는지 본다. “현재 이웃에서 더 좋아지는 이동을 찾지 못함”은 전역 최적 증명이 아니다.

## 다양한 시작과 수용 규칙

### 다중 시작·무작위 탐욕·GRASP

동률 순서나 초기 배치를 달리해 여러 해를 만들고 각각 개선한다. 하나의 초기값에 갇히는 문제를 줄일 수 있다. 무작위 seed와 반복 횟수, 공통 전체 예산을 기록한다. 가장 좋은 seed 하나만 골라 일반 성능처럼 보고하지 말고 실행별 유효성·품질·시간의 분포를 확인한다.

### Simulated annealing

일부 나빠지는 이동도 확률적으로 받아들여 국소 함정에서 벗어나려는 방법이다. 온도와 목적의 단위가 달라지면 수용률이 달라진다. 제한된 실행에서 전역 최적 보장을 주장하지 않는다. 탐색의 현재 해가 나빠져도 최선의 검증된 해는 별도로 보존한다. 연속함수용 라이브러리의 annealing API를 순열·배정 문제에 그대로 적용하지 않는다. [SciPy dual annealing의 입력 계약](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.dual_annealing.html)

### Tabu search·threshold acceptance

최근 움직임을 잠시 금지하거나 정한 허용 악화 범위 안에서 이동해 순환을 줄인다. tabu 길이·금지 단위·예외 수용 기준이 탐색에 영향을 준다. 금지 규칙은 업무 필수 제약이 아니라 탐색 장치이므로 결과 설명에서 구분한다. 탐색이 멈췄다면 후보가 막힌 이유와 유효 해 존재를 각각 보고한다.

### Beam search

단계별로 유망한 부분 해 일부만 유지한다. 상태 수를 줄일 수 있지만 버린 부분 해에 최적해가 있었을 수 있다. beam 폭은 품질·메모리·시간의 절충이며, 현재 점수가 비슷한 서로 다른 구조의 해를 어떻게 보존하는지도 중요하다. 상한으로 안전하게 가지치는 정확 탐색과 구분한다.

### 진화·유전 알고리즘

여러 후보를 유지하고 조합·변이를 반복한다. 조합 연산이 중복·누락·금지 배정을 만들 수 있으므로 표현·복구·검증을 함께 설계해야 한다. 목적 평가가 비싸면 큰 집단과 세대 수가 빠르게 비용을 소진한다. 단순 탐색보다 나은지 실제 문제에서 확인한 경우에 사용하고 이름만으로 강력한 방법이라고 추천하지 않는다.

## 크게 바꾼 뒤 복구

### LNS·ALNS

일부 배정을 제거한 뒤 그 부분을 새로 채운다. 무작위 제거, 가까운 대상 제거, 비용이 큰 묶음 제거처럼 다른 구조를 시도할 수 있다. ALNS는 제거·복구 방법의 관측 성과로 선택 비중을 조정한다. 실제 유효성과 개선은 문제별 복구 연산에 달려 있다. [저자 논문: Ropke·Pisinger의 ALNS](https://orbit.dtu.dk/files/3154899/An%20adaptive%20large%20neighborhood%20search%20heuristic%20for%20the%20pickup%20and%20delivery%20problem%20with%20time%20windows_TechRep_ropke_pisinger.pdf), [ALNS 프로젝트 문서](https://alns.readthedocs.io/en/latest/)

실패한 복구가 기존 전체 해를 지우지 않게 복사 또는 되돌리기 경계를 둔다. 제거되지 않은 대상을 무조건 고정하면 더 나은 전체 재편성을 막을 수 있으므로 일부 실험에서는 고정 범위도 바꾸어 비교한다. 라이브러리 도입 여부는 설치 환경과 실제 필요에 따라 판단하며 모형 없이 프레임워크만 추가하지 않는다.

### 정확 복구·matheuristic

전체 문제는 휴리스틱으로 처리하고 막힌 작은 부분만 완전탐색·매칭·정수 모형으로 푼다. 부분 문제의 경계 자원과 고정된 다른 대상의 점유를 포함해야 한다. 작은 부분의 최적 해가 전체의 최적 해라는 뜻은 아니다. 복구 후 전체 검증을 통과할 때만 새 후보로 보존한다.

### Rolling horizon·재최적화

미래 전체 대신 일정 구간을 풀고 새 정보가 오면 이동해 다시 계산한다. 이미 실행 중인 작업·확정 약속·취소 비용을 구분한다. 구간 끝 바깥으로 비용을 밀어내거나 미래 자원을 공짜처럼 사용하지 않게 종료 조건·예약 자원을 모델에 넣는다. 변경량을 줄이는 안정성 목표도 필요하면 사용자와 정한다.

## 미처리 회복의 단계

1. 원본 누락·ID 오류·후보 생성 제한·탐색 시간 부족·실제 조건 충돌을 구분한다. 미발견을 불가능으로 바꾸지 않는다.
2. 필수 조건을 유지한 채 후보 확대·재배정·다른 순서·기존 유효 후보 복원을 시도한다.
3. 승인된 사용자 정책의 조정 범위 안에서만 완화·예외를 자동 적용한다. 새로운 중요한 완화는 실제 효과와 부담을 설명하고 결정을 받는다.
4. 예외는 현재 대상과 최종 묶음에 다시 판정하고, 동시에 적용한 전체 결과에서 다른 대상의 누락과 부담을 검사한다.
5. 필수 조건을 만족한 결과만 적용한다. 끝내 충족하지 못하면 부분 결과·실패 이유·미확인 상태를 구분해 보존한다.

사용자와의 대화는 반복 실행 가능한 규칙을 정하는 데 쓴다. 정상 재계산마다 개발자가 개별 명단을 승인해야만 돌아가는 서비스를 만들지 않는다. 현재 입력에서 어떤 대상이 예외에 해당하는지 프로그램이 계산하고 근거를 남긴다.

## 시뮬레이션으로 결과를 평가

### 이산 사건 시뮬레이션

도착·시작·완료·취소처럼 상태가 바뀌는 사건 시점으로 이동한다. 사건 `e`개를 우선순위 큐로 처리하는 기본 구조는 큐 연산에 `O(e log e)`가 들고 사건 처리 비용이 추가된다. 같은 시각의 순서, 종료 직전 사건, 재시도·취소 이벤트의 중복 적용을 명시한다. 시뮬레이션 속 자원의 동시 진행과 실제 프로그램 스레드의 병렬 실행은 다르다. [SimPy 시간·이벤트 처리 설명](https://simpy.readthedocs.io/en/latest/topical_guides/time_and_scheduling.html)

### 대기열과 부하 실험

도착률·처리시간·자원 수·우선순위에 따라 평균·최악 대기, 처리량, 포기율을 관찰한다. 평균 처리시간만으로 긴 꼬리와 몰리는 수요를 지우지 않는다. 단순 큐 모형의 수학적 결과는 정상상태·도착·서비스 분포 가정 안에서 해석한다. 업무 시스템의 실제 부하 테스트와 모의 대기열 결과를 혼동하지 않는다.

### Monte Carlo·공통 난수 비교

불확실한 수요·처리시간을 여러 번 생성해 정책 결과를 비교한다. 분포와 파라미터의 근거를 기록하고, 같은 시나리오·난수 흐름으로 후보를 비교하면 차이의 해석을 도울 수 있다. 하나의 좋은 실행으로 안정성을 주장하지 않는다. 표본 평균·분산·분위수의 추정 오차와 극단 조건을 따로 살핀다.

### 시나리오·민감도·스트레스

용량 감소, 특정 연결 단절, 수요 집중, 처리시간 증가, 입력 순서 변경 등 의미 있는 변화를 준다. 실제 가능한 범위와 설명용 극단을 구분한다. 각 시나리오의 전체 대상·필수 조건·미처리 원인·목표 값을 비교하며, 통과한 시나리오 집합을 넘어 모든 상황을 보장하지 않는다.

## 공정한 비교와 종료

전체 실행시간은 후보 생성·거리 계산·탐색·검증·저장을 포함한다. 같은 하드웨어·입력·설정·정책과 공유 예산에서 비교하고, 병렬 실행이면 총 자원 사용과 응답시간을 구분한다. 캐시 유무, warm start, seed, 실험 횟수를 기록한다. 새 후보가 개선되면 실제 서비스 계산 경로에 연결해 통합 검증한 뒤 다음 선택적 개선으로 넘어간다.

개선이 없다는 사실, 구현 오류, 시간 제한, 필수 조건 위반, 입력 불가능을 각각 보고한다. 유효한 이전 해를 보존하면서 종료 조건에 도달하면 멈춘다. “더 돌리면 좋아질 수 있다”만으로 무한 반복하지 않는다. 준비 자료의 범위를 넓히는 일과 실제 작업 실행 예산을 무한히 쓰는 것은 별개다.

## 대표 반례

- 평균 비용만 줄었지만 미처리가 생김: 처리 범위가 달라 공정한 개선 비교가 아님.
- 비대칭 경로의 2-opt가 끝 간선만 계산함: 실제 순서를 전수 재계산해 차이 확인.
- 무작위 한 번만 성공: 여러 고정 seed에서 유효성·분포 확인.
- 지역 이동 후 예외 대상이 빠졌는데 예외가 유지됨: 최종 구성원으로 재판정.
- 시뮬레이션상 요청 중복이 없으므로 실제 서버도 안전하다고 판단함: 서버·저장 경합은 별도 실행 검사.
- 현재 설정에서 실패해 옛 설정의 결과를 자동 적용함: 결과 버전과 실제 적용 조건 불일치.
