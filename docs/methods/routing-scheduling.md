# 경로와 일정

방문 순서, 시작 시각, 자원 점유가 결과를 바꿀 때 읽는다. 두 지점의 최단경로, 여러 지점을 방문하는 순서, 여러 자원에 작업을 나누는 일정은 서로 다른 문제다. 이 문서는 후보 방법을 고르는 참고자료이며 아래 모든 방법이 구현되어 있다는 뜻은 아니다.

## 입력부터 구분하기

- 이동비용이 거리인지 시간인지, 방향에 따라 달라지는지, 출발 시각에 따라 변하는지 확인한다. 결측 구간을 0으로 채우지 않는다.
- 경로가 출발점으로 돌아오는지, 시작·종료가 다른지, 반드시 방문할 대상과 선택 가능한 대상이 무엇인지 정한다.
- 용량이 총 배정량인지 시점별 적재량인지, 자원이 동시에 여러 작업을 할 수 있는지 확인한다.
- 날짜·시간대·야간 작업·경계 포함 여부와 서비스 처리시간을 실제 의미대로 해석한다. 관리자가 바꿀 수 있는 여유시간·용량은 매 실행의 설정으로 받는다.

## 방문 순서를 만드는 방법

### 최근접·가장 저렴한 삽입·regret 삽입

최근접은 현재 위치에서 가까운 미방문 대상을 고른다. 저렴한 삽입은 현재 경로의 어느 사이에 대상을 넣을 때 비용이 덜 늘어나는지 본다. regret 삽입은 최선 자리를 잃으면 손해가 큰 대상을 먼저 처리한다. 작은 기준선을 만들기 좋지만 먼 대상·촉박한 대상이 마지막에 남거나 초기 순서에 묶일 수 있다.

전형적인 단순 구현에서 최근접 전체 구성은 `O(n²)`, 모든 대상·위치를 반복 검사하는 삽입은 `O(n³)`까지 들 수 있다. 실제 제약 검사 비용이 추가된다. 한 점을 넣을 때 용량만 보지 말고 이후 도착시간, 서비스시간, 대상별 우회, 최종 귀환을 함께 전파해 검사한다.

### 절감량 기반 병합

처음 별도 경로로 처리하던 두 묶음을 합쳤을 때 줄어드는 비용을 보고 병합한다. 고전적인 savings 발상은 빠른 초기 경로 후보를 만드는 데 유용하다. 방향별 비용·다른 시작점·시간창이 있으면 단순 대칭 공식을 그대로 사용하지 않는다. 후보 쌍은 `O(n²)` 규모가 될 수 있으며, 병합 후 모든 현재 구성원의 조건을 재검증한다. 기존 좋은 경로도 후보로 보존해 제로베이스 탐색의 후보 부족을 줄인다.

### TSP 완전탐색과 Held–Karp DP

작은 방문 집합의 정확 검산에 쓴다. 순열 열거는 팩토리얼로 증가하고, 방문 집합과 마지막 지점의 DP는 `O(n² 2^n)` 시간·`O(n 2^n)` 공간을 쓴다. `n`이 조금 늘어도 급격히 커지므로 실행 전 상태 수를 계산한다. 방향성, 시작·종료, 닫힌 순회인지의 계약을 동일하게 맞춘다. 큰 경로 문제의 전체 최적성 근거로 작은 부분 문제의 최적값을 제시하지 않는다.

### metric TSP 근사와 최단경로 폐포

무방향·대칭·삼각부등식이 성립하는 거리에서 MST 기반 또는 Christofides 계열 근사를 검토할 수 있다. 이 조건에서의 보장을 비대칭 시간표나 시간창·용량이 있는 문제로 옮기지 않는다. 원래 그래프를 지점 간 최단거리로 바꾸는 폐포가 중간 필수 지점을 통과할 수 있으므로 실제 경로 복원과 중복 방문 의미를 확인한다. 단순 직선거리가 실제 도달 가능성을 증명하지 않는다.

## 여러 경로를 함께 편성하기

### CVRP와 이질 자원

자원별 용량을 지키며 여러 대상을 경로에 나누어 담는다. 단일 수요·동일 용량부터 시작하고, 여러 화물 차원이나 자원별 다른 용량은 실제 필요할 때 확장한다. 총 수요/용량을 올림한 값은 특정 가정의 하한일 뿐, 시간창·허용 연결 때문에 그 수로 가능한지는 별도 문제다. [OR-Tools 용량 경로 안내](https://developers.google.com/optimization/routing/cvrp)

### 시간창 경로 VRPTW

도착 또는 서비스 시작이 허용 구간 안에 있어야 한다. 일찍 도착한 경우의 대기, 구간 끝의 포함 여부, 처리 완료까지 창 안이어야 하는지를 구분한다. 시간 누적값과 여유값을 검증하고 최종 저장 시각을 원래 날짜·시간대로 복원한다. 시각을 버리고 이동시간 합만 검사하면 시간창을 통과했다고 할 수 없다. [OR-Tools 시간창 안내](https://developers.google.com/optimization/routing/vrptw), [누적량과 대기 모델](https://developers.google.com/optimization/routing/dimensions)

### 수거·전달과 승하차

쌍을 이루는 시작·종료가 있으면 같은 자원 사용, 시작 이전 종료 금지, 시점별 적재량, 대상별 체류시간을 검사한다. 총 처리 대상 수가 용량보다 많아도 중간에 내려주면 가능할 수 있고, 반대로 최종 순증가량만 0이어도 중간 과적은 발생할 수 있다. 순서대로 원래 수요 증감을 누적하는 독립 검산이 필요하다. [OR-Tools pickup–delivery 예제의 제약 구조](https://developers.google.com/optimization/routing/pickup_delivery)

### 후보 경로 생성 후 조합 선택

유효한 경로 후보를 만든 뒤 각 대상을 정확히 한 번 처리하는 조합을 정수 모형으로 선택할 수 있다. 후보를 좁혀 빠르게 풀 수 있지만 해의 품질과 가능성은 후보 집합에 제한된다. 미처리가 나오면 후보 누락·탐색 부족과 실제 조건 충돌을 구분한다. 시간 여유가 있으면 기존 유효 경로, 미처리 대상 전용 후보, 대체 순서 후보를 추가해 재검토한다.

### 제한 시간의 경로 솔버

초기해 전략과 개선 탐색을 분리해 현재 유효 결과를 먼저 보존한다. 경로 솔버가 제한 시간 안에 반환한 해가 전역 최적이라는 뜻은 아니다. 필수 방문을 빼는 벌점 옵션은 실제로 누락이 허용되는 경우에만 사용한다. 시간 제한을 늘리는 것은 불가능한 조건을 가능하게 바꾸는 조치가 아니다. [OR-Tools 경로 문제의 범위와 한계](https://developers.google.com/optimization/routing), [검색 옵션](https://developers.google.com/optimization/routing/routing_options)

## 시간과 자원을 배치하기

### 구간 선택과 가중 구간 일정

한 자원에서 겹치지 않는 최대 개수의 고정 구간을 고르는 문제는 종료 시각 순 탐욕법을 검토한다. 구간마다 가치가 다르면 앞선 호환 구간을 찾는 DP가 필요하다. 정렬·이분 탐색을 포함해 보통 `O(n log n)`에 처리할 수 있다. 시작 시각을 이동할 수 있거나 여러 자원·선행 조건이 결합되면 이 모형만으로 풀리지 않는다. 반개구간 `[시작, 끝)`에서 끝과 다음 시작이 같은 경우를 별도로 검사한다.

### 구간 분할·최소 자원 수

모든 고정 구간을 처리하면서 동시에 필요한 자원 수를 줄일 때, 시작순 처리와 종료 시각 힙을 사용할 수 있다. 동시 겹침 수는 해당 단순 모형의 필요한 자원 수와 연결된다. 준비시간·자원 자격·이동시간이 있으면 구간을 그대로 재사용하지 않는다. 단순 예약 시스템의 기준선과 동시 점유 검산에 유용하다.

### 선행 관계와 임계 경로

작업 DAG의 선행 완료를 따라 가능한 가장 이른 시각을 구한다. 자원 충돌이 없고 기간이 고정일 때 위상순 DP는 `O(V+E)`. 순환은 입력 오류 또는 별도 반복 공정 의미로 처리한다. 임계 경로 길이는 자원 제한 일정의 하한이 될 수 있지만 자원이 부족한 실제 완료시간과 같다고 할 수 없다.

### 우선순위 디스패칭과 list scheduling

현재 실행 가능한 작업 중 짧은 작업·마감이 빠른 작업·남은 여유가 작은 작업 등을 골라 빈 자원에 배치한다. 빠른 유효 기준선에 적합하고 정책별 평균 대기·최대 지연을 비교하기 쉽다. SPT·EDD 등의 보장은 목적과 단일/다중 자원, 도착 시각 등 가정에 따라 달라진다. “짧은 작업 먼저”가 모든 환경의 최적 규칙이라고 쓰지 않는다.

### Job shop·flow shop·자원 제한 프로젝트

작업 순서, 기계 점유, 선택 가능한 기계, 준비시간, 휴식·정비 달력이 함께 있으면 CP·MILP 또는 전용 휴리스틱을 검토한다. 작업별 선행과 기계별 겹침 금지는 별개다. 선택 작업이 존재하지 않는데 그 시간구간이 다른 작업을 막거나, 기계 선택과 일정이 서로 어긋나지 않게 연결한다. [OR-Tools job shop 모델](https://developers.google.com/optimization/scheduling/job_shop)

### 근무·인력 일정

날짜·시간대별 필요 인원과 자격, 한 사람의 중복 배치, 휴식과 선호를 구분한다. 충족 의무를 낮춰 좋은 균형 점수를 얻지 않도록 목적 순서를 정한다. 기간 경계 바깥의 직전 근무가 현재 휴식 규칙에 영향을 주는지도 확인한다. [OR-Tools 인력 일정 예제](https://developers.google.com/optimization/scheduling/employee_scheduling)

### 시간 인덱스 모형과 구간 모형

시간 인덱스는 작업이 각 슬롯에 시작하는지 표현해 읽기 쉽지만 슬롯 수에 따라 변수가 증가한다. 구간 모형은 시작·기간·종료와 겹침 관계를 직접 표현한다. 분 단위로 쪼갰다고 원래 초 단위 문제를 정확히 풀었다고 하지 않는다. 허용하는 이산화 오차와 경계 조건을 기록한다.

## 작은 반례와 검산

- 두 방향의 이동시간이 다른 입력: 경로를 뒤집어 비용을 재사용하면 안 됨.
- 용량은 맞지만 마지막 대상이 마감에 늦는 입력: 각 지점의 누적시간 재계산.
- 같은 시각에 한 자원이 두 작업을 수행하는 입력: 저장된 자원별 구간으로 충돌 검사.
- 종료가 다음 날인 작업: 표시 날짜와 업무 귀속 날짜를 분리하고 실제 순서를 확인.
- 작은 총거리지만 특정 대상의 체류시간이 큰 경로: 총합과 최대·분포를 함께 비교.
- 부분 탐색에서 남은 대상: 기존 유효 해를 버리지 않고 후보 확대·승인된 정책 안의 회복을 시도.

## 서비스 연결

입력·설정·정책을 한 실행의 고정 스냅샷으로 계산하고 결과에 버전을 남긴다. 새 설정으로 실행한 결과가 적용된 뒤 옛 실행이 늦게 끝나도 덮어쓰지 않는 정책을 구현한다. 지도 선이나 일정표 그림만으로 계산의 타당성을 검증하지 말고 저장된 순서·시각·자원·대상을 검사한다. 오프라인 개선 함수를 실제 재계산 경로에 연결한 뒤 같은 입력의 결과와 동작을 확인한다.

사용자에게는 “총 이동을 줄이는 동안 가장 오래 기다리는 대상의 부담은 어디까지 허용할까요?”처럼 실제 절충을 설명한다. 기존에 확정된 마감·용량을 다시 협상하거나 새 제한을 몰래 만들지 않는다.
