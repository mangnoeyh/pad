# 구간·시간·반복 질의

데이터가 한 번 정해지는지, 변경과 질의가 번갈아 오는지, 모든 질의를 미리 아는지로 나눈다. `n`은 원소/구간 수, `q`는 질의 수, `k`는 출력 수다. 구간은 기본적으로 `[시작, 끝)` 같은 명시된 규약으로 표현하되 실제 요구를 우선한다. 시각 문자열 정렬 전에 날짜·타임존·자정 경계와 업무일을 확정한다.

## 빠른 선택

| 입력·연산 | 먼저 검토 | 변경될 때 |
| --- | --- | --- |
| 정적 구간 합 | 누적합 | 점 갱신이면 Fenwick |
| 정적 구간 최솟값 | 직접 탐색 또는 sparse table | 갱신이면 segment tree |
| 예약 겹침·최대 동시 수 | 정렬·스위프 | 온라인 반복 질의면 인덱스 |
| 가장 많은 겹치지 않는 일정 | 종료시각 탐욕 | 가치가 다르면 가중 일정 DP |
| 임의 순위·앞뒤 이웃 삽입/삭제 | 균형 검색 트리 | 실행 환경의 실제 자료구조 확인 |
| 트리 경로 갱신·조회 | Euler 순회·HLD와 구간 구조 | 실제 트리인지 확인 |

## R01 — 구간 병합·교집합

- **목적:** 중복 운영 시간 통합, 허용 기간의 합집합·겹치는 구간 계산. 정렬 후 병합 `O(n log n)`, 이미 정렬된 두 구간 목록 교집합은 `O(n+m+k)`.
- **조건:** 끝과 다음 시작이 같은 구간을 합칠지, 길이 0 구간이 유효한지 정한다. 날짜별로 반복되는 일정과 절대시각 구간은 다르다.
- **반례:** `[1,3)`과 `[3,5)`는 겹치지 않지만 합집합 표현으로 합칠 수는 있다. 충돌 탐지와 표시 단순화에 같은 조건을 쓰면 잘못된 경고가 생긴다.
- **검산·연결:** 작은 정수 시간축을 직접 표시해 합집합·교집합을 비교한다. 원본 예약 ID를 잃으면 변경·취소를 처리하기 어려우므로 집계와 원본을 분리한다.

## R02 — 스위프 라인과 사건 정렬

- **목적:** 최대 동시 요청 수, 중첩 구간, 시간대별 사용량. 시작/종료 사건을 정렬하고 상태를 갱신해 `O(n log n)`.
- **조건:** 같은 시각에 종료를 먼저 처리할지 시작을 먼저 처리할지는 경계 규약에 따른다. 비정상 음수 사용량은 입력 또는 사건 순서 오류일 수 있다.
- **반례:** 예약 종료 직후 새 예약이 가능한데 시작 사건부터 처리하면 자원을 하나 더 요구한다고 계산한다.
- **검산·연결:** 모든 사건 직전·정각·직후 사용량을 작은 직접 계산과 비교한다. 용량 최대치뿐 아니라 위반 시작·끝 구간과 원인 ID를 반환하면 화면에서 조치할 수 있다.

## R03 — 구간 선택과 구간 분할

- **목적:** 한 자원에서 최대 개수의 서로 겹치지 않는 일정은 종료가 빠른 순서로 선택한다. 모든 일정을 최소 개수 자원에 넣는 구간 분할은 시작순 정렬과 가장 이른 종료 힙을 쓴다. 일반 구현은 `O(n log n)`.
- **조건:** 첫 문제는 각 일정의 가치가 같고 한 자원인 기본형이다. 두 번째는 동일한 자원이 각 구간을 처리할 수 있어야 한다.
- **반례:** 수익이 다르면 최대 개수 선택이 최대 수익은 아니다. 자원별 자격·이동시간·준비시간이 있으면 기본 탐욕의 보장을 그대로 옮길 수 없다.
- **검산·연결:** 작은 부분집합 열거와 비교한다. 선택 문제인지 모든 일정을 반드시 처리해야 하는 문제인지 먼저 설명한다.

## R04 — 가중 구간 일정

- **목적:** 겹치지 않는 일정들의 총 가치 최대화. 종료순 정렬 후 각 일정 직전 호환되는 마지막 일정을 이분 탐색하고, 포함/미포함 DP를 계산한다. `O(n log n)` 시간, `O(n)` DP 저장이 기본이다.
- **조건:** 한 자원의 비중첩 구간과 가산 가치. 시간 경계를 정하고 선택 ID를 복원한다.
- **반례:** 일정 A의 가치가 8이어도 서로 안 겹치는 B·C 가치가 각각 5이면 A만 고르는 탐욕은 손해다. 여러 자원·순서별 비용·필수 동시 선택은 상태/모형을 확장해야 한다.
- **검산:** 모든 작은 부분집합의 충돌·가치를 검사해 대조한다. [TU Delft의 DP 자료](https://ocw.tudelft.nl/course-lectures/5-dynamic-programming/)는 가중 구간과 배낭 등 서로 다른 상태 설계를 구분한다.

## R05 — Fenwick tree / Binary Indexed Tree

- **목적:** 수치 배열의 점 증감과 prefix/range 합을 반복 처리. 일반 갱신·질의 `O(log n)`, 저장 `O(n)`; 구성은 구현에 따라 `O(n)` 또는 `O(n log n)`.
- **조건:** 구간 합은 두 prefix의 차로 표현한다. 외부 0-based와 내부 1-based 인덱스가 섞이지 않게 경계를 한 곳에서 변환한다.
- **반례:** 임의 대입을 증가 연산으로 넣으면 이전 값이 중복된다. 임의 최솟값 갱신은 합용 Fenwick의 같은 인터페이스로 처리되지 않는다.
- **검산·연결:** 무작위 갱신·질의를 일반 리스트와 비교한다. 빈 구간·끝점·음수 증감·좌표 압축 후 질의를 포함한다. 저장 데이터 변경과 인덱스 갱신의 일관성을 유지한다.

## R06 — Segment tree와 lazy propagation

- **목적:** 결합 가능한 구간 합·최소·최대와 갱신. 기본 segment tree는 구성 `O(n)`, 점 갱신·구간 질의 `O(log n)`, 저장 `O(n)`. lazy propagation은 지원하는 구간 갱신을 미뤄 처리한다.
- **조건:** 결합 연산의 순서·결합법칙·항등원을 정한다. 구간 대입과 구간 덧셈을 함께 지원한다면 미뤄둔 연산의 합성 순서가 중요하다.
- **반례:** 구간 평균을 길이 정보 없이 결합하면 틀린다. 최솟값 구간에 덧셈은 단순하지만, 구간 합에 덧셈은 구간 길이까지 곱해야 한다.
- **검산:** 작은 배열에서 모든 갱신을 직접 적용한 뒤 조회한다. 대입→증가와 증가→대입, 전체/부분 중첩을 검사한다. 복잡한 lazy 연산은 필요할 때만 도입한다.

## R07 — Sparse table / 정적 RMQ

- **목적:** 변경 없는 배열의 반복 최솟값·최댓값 등 idempotent 질의. 일반 sparse table은 구성·공간 `O(n log n)`, 겹치는 두 블록으로 RMQ 질의 `O(1)`.
- **조건·반례:** 두 블록이 겹쳐도 같은 값의 중복 결합이 영향을 주지 않아야 한다. 합에 같은 `O(1)` 공식을 적용하면 겹친 항목을 두 번 센다. 합은 누적합이 단순하다.
- **검산·연결:** 길이 1, 2의 거듭제곱 전후, 동률 위치를 직접 탐색과 비교한다. 배열 변경 후 오래된 표를 재사용하지 않는다. [Stanford RMQ 강의](https://web.stanford.edu/class/cs166/lectures/00/Slides00.pdf)는 전처리·질의 비용의 교환을 다룬다.

## R08 — 균형 검색 트리·순위 통계

- **목적:** 삽입·삭제가 있는 정렬 집합, 전임/후임, k번째 원소, 범위 개수. 균형 이진 검색 트리의 기본 연산은 `O(log n)`; 순위 질의에는 서브트리 크기 같은 추가 정보가 필요하다.
- **조건:** 중복 값을 별도 ID로 저장할지 빈도로 저장할지 정한다. Python 표준 리스트+bisect는 정렬 삽입·삭제가 `O(n)`이라는 점을 고려한다.
- **반례:** 일반 BST를 정렬된 순서로 삽입하면 편향돼 선형 깊이가 될 수 있다. 힙은 임의 순위 질의용 정렬 트리가 아니다.
- **검산:** 정렬된 리스트 기준으로 혼합 연산을 비교한다. 환경에 검증된 구현이 없으면 직접 복잡한 균형 트리를 만들 비용과 단순 방식의 실측을 비교한다. [Princeton의 균형 검색 트리 설명](https://algs4.cs.princeton.edu/33balanced/).

## R09 — 제곱근 분할·Mo 방식

- **목적:** 구간 연산을 블록으로 나누거나, 순서를 바꿀 수 있는 오프라인 질의를 가까운 구간끼리 처리. 단순 블록 분할은 연산에 따라 `O(√n)` 수준. 정적 Mo의 일반 정렬과 양끝 이동은 대략 `O((n+q)√n)` 이동 비용이며 추가/삭제 한 번의 비용을 곱한다.
- **조건:** 원래 질의 순서를 결과 ID로 복원한다. Mo는 구간 상태의 한 원소 추가·삭제가 싸고 정확해야 한다.
- **반례:** 앞 질의 답에 따라 다음 입력이 결정되는 온라인 요청을 마음대로 재정렬할 수 없다. 배열 수정이 끼면 기본 Mo 조건과 다르다.
- **검산:** 직접 구간 계산 기준과 비교한다. 우선 단순 구조로 충분한지 확인한 뒤 상수·메모리·정렬 비용까지 측정한다.

## R10 — Euler 순회·HLD·지속 자료구조

- **Euler 구간화:** 정적 루트 트리의 서브트리를 연속 구간으로 매핑한다. 전처리 `O(n)`이며 이후 구간 자료구조를 재사용한다. 루트나 간선이 바뀌면 매핑이 달라진다.
- **HLD:** 트리 경로를 `O(log n)`개 heavy chain으로 나누고 구간 구조와 결합한다. 기본 segment tree 질의와 합치면 경로 연산은 흔히 `O(log² n)`. 방향에 민감한 결합은 조각의 순서를 보존한다.
- **지속 segment tree:** 과거 버전을 보존하며 점 변경마다 일반적으로 `O(log n)`개 노드를 복사한다. 메모리는 초기 `O(n)`에 변경 횟수×`log n`이 추가된다. 업무 이력 저장·권한·동시 변경 충돌을 자동 해결하는 DB는 아니다.
- **검산:** 작은 트리의 실제 경로를 직접 걷고, 옛 버전 질의 결과가 새 갱신으로 변하지 않는지 확인한다. 동적 트리·link-cut tree는 구조 변경 질의가 실제 병목인 경우에만 별도 조사한다.

## R11 — 이산 사건 시뮬레이션

- **목적:** 도착·완료·자원 반환처럼 상태가 바뀌는 시각만 처리한다. 사건 `e`개에 힙을 쓰면 기본 처리 `O(e log e)`에 사건별 상태 계산 비용이 더해진다.
- **조건:** 같은 시각의 사건 순서, 재시도, 자원 재사용 시점, 종료 조건을 정의한다. 단위시간마다 전부 갱신하는 시뮬레이션보다 빠를 수 있지만 사건 수 자체가 폭발할 수도 있다.
- **반례:** 완료와 새 도착의 동률 순서를 바꾸면 대기시간이 달라진다. 시뮬레이션은 입력 가정 아래 결과를 관찰하며 스스로 최적 스케줄을 찾지는 않는다.
- **검산·연결:** 작은 시간축 직접 시뮬레이션, 자원 총량 보존, 음수 대기 금지, 모든 요청의 단일 종료를 확인한다. 실제 시스템의 재현 로그와 합성 사건을 구분한다.

## 기준을 물어볼 때

“종료 정각부터 다음 요청을 받을 수 있나요?”처럼 결과가 갈리는 경계를 묻는다. 업무일과 실제 날짜, 예약 기간과 처리 시각을 혼동하지 않는다. 자료구조 선택은 이미 합의한 시간 의미를 빠르게 계산하는 수단이며 동률·중복·충돌의 업무 기준을 새로 만드는 근거가 아니다.

분야 범위 확인에는 [저자 교재](https://cses.fi/book/book.pdf)의 구간·트리 관련 목차도 참고했다. 예시와 적용 판단은 독자 작성이며 코드 구현을 포함하지 않는다.
