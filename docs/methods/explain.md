# 방법을 쉽게 설명하고 선택하기

이름이나 수식을 먼저 암기할 필요는 없다. 메인은 현재 문제를 작은 사례로 바꾸고, 방법이 어떤 선택을 하는지와 무엇을 놓칠 수 있는지 보여준다. 실제 사용자 이해는 대화에서 확인하며 문서가 생성됐다고 추정하지 않는다.

낯선 말은 [용어 풀이](glossary.md)에서 현재 설명에 필요한 것만 확인한다. 사용자가 알고리즘 이름을 알아야 운영상 선택에 답할 수 있게 만들지 않는다.

## 설명의 기본 단위

**지금 결과에서 보이는 점 → 추천과 작동 방식 → 좋아지는 점과 부담 → 중요한 결정 하나** 순서로 설명한다. 사실 확인 문안과 사용자의 운영 선택은 구분한다. 이미 합의한 기준 안의 일반 기술 선택은 이유를 알리고 진행한다.

예를 들어 대상 A는 자원 X와 Y를 쓸 수 있고 B는 X만 쓸 수 있다. A를 먼저 X에 배정하면 B가 남을 수 있다. “선택지가 적은 대상을 먼저 보거나, A를 Y로 옮기는 재배정을 검토하겠습니다”라고 설명할 수 있다. 이 작은 예시가 모든 입력에서 해당 순서의 최적성을 증명하는 것은 아니다. 실제로는 비교와 검산이 필요하다.

| 사용자에게 필요한 이해 | 설명할 내용 | 피할 설명 |
| --- | --- | --- |
| 탐색·최단경로 | 연결된 후보를 따라가며 누적 비용을 비교 | 거리가 짧으면 모든 운영 조건도 자동 만족 |
| 동적 계획 | 같은 중간 상황의 최선 값을 재사용 | 어떤 과거 정보든 버려도 됨 |
| 매칭·흐름 | 한 선택을 바꿔 다른 대상의 자리를 확보 | 용량만 맞으면 시간·그룹 조건도 해결 |
| 제약 최적화 | 바꿀 선택과 지킬 규칙을 함께 표현 | 솔버를 쓰면 항상 최적해가 즉시 나옴 |
| 지역 개선 | 현재 해에서 일부 선택을 바꿔 더 나은 해 탐색 | 더 이상 좋아지지 않으면 전역 최적 |
| 후보 생성·군집 | 볼 조합을 줄이거나 초기 묶음을 만듦 | 후보에서 빠진 대상은 원래 불가능 |

## 실제 코드와 연결

대표 입력 한 건을 읽기·형식 변환·허용 후보·계산·독립 검증·저장·표시까지 추적한다. 실제 파일·함수·입출력을 연결하고, 구현하지 않은 단계를 설명에 넣지 않는다. 입력·설정을 바꿨을 때 같은 함수가 어디에서 다시 호출되는지 보여준다.

완료 후 [전체 해설](../../templates/solution-review.md)에는 채택 이유, 단순 기준선과의 실제 차이, 사용자 결정, 적용한 일반 예외, 미검증·한계를 담는다. 상세 계산은 필요한 곳에서 펼치고 첫 요약에는 흐름과 근거만 남긴다.

질답 연습에서는 “왜 이 방법인가?”, “어떤 경우 틀리거나 느려지는가?”, “설정이 바뀌면 어디가 다시 계산되는가?”, “AI 제안 중 내가 바꾼 기준은 무엇인가?”처럼 현재 구현에 해당하는 질문을 고른다. 한 번에 하나의 개념을 다루고, 실제로 없었던 선택이나 검사 결과를 모범답안에 만들지 않는다.

## 두 트랙에서의 역할

사용자가 목표·현실 가정·중요한 운영 절충을 결정하면 메인은 이를 현재 정책과 검증 조건으로 바꿔 관련 워커에게 전달한다. 워커는 비교·구현을 계속하고, 메인은 실제 진전과 새로 발견한 문제를 짧게 설명한다. 새 답변에 의존하는 작업만 기다린다. 준비된 자료가 넓다는 이유로 모든 알고리즘 설명을 사용자에게 순서대로 강의하지 않는다.
