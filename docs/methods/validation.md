# 계산 결과와 성능을 확인하기

이 자료는 선택한 방법의 결론을 뒷받침할 때 읽는다. 모든 방법에 모든 검사를 적용하는 목록이 아니다. 입력과 의미의 검증은 기존 [데이터 지침](../../.agents/skills/data-triage/SKILL.md), 후보 비교는 [비교 양식](../../templates/candidate-comparison.md)을 함께 사용한다.

## 서로 다른 네 가지 질문

1. **문제 표현이 맞는가:** 선택할 변수, 대상 범위, 단위, 필수 조건과 사용자의 선호가 실제 요구와 일치하는가?
2. **구현이 맞는가:** 표현한 문제에 대해 코드가 올바른 결과를 계산하는가?
3. **현재 결과가 유효한가:** 저장된 결과를 현재 입력·설정으로 다시 검사했을 때 모든 필수 조건과 처리 범위를 만족하는가?
4. **품질·속도가 충분한가:** 현재 규모·환경에서 기준선보다 어떤 이득과 부담이 있고 어떤 범위까지 확인했는가?

작은 함수의 테스트 통과가 네 질문 모두에 대한 답은 아니다. 정확한 알고리즘으로 잘못된 수요를 최적화해도 업무 문제를 해결하지 못한다.

## 작은 정확 해와 비교

독립 구현의 전수 탐색·간단한 DP로 정답을 계산할 수 있는 작은 입력을 만든다. 예를 들어 부분집합을 모두 보는 배낭 검산과 테이블을 채우는 DP는 서로 다른 경로를 사용한다. 후보 생성기와 검사기가 같은 계산을 호출하면 동일한 오류를 놓칠 수 있다.

전수 탐색은 시작 전에 조합 수 또는 보수적 상한을 추산한다. 전체 열거를 허용하지 않는 크기면 `미실행`으로 남기고, 가지치기처럼 실제 탐색 수를 미리 알기 어려우면 노드·시간·메모리 중단 예산을 둔다. 중단된 탐색은 완료한 정확 검산과 구분한다. 작은 경우에 맞았다는 사실을 큰 입력의 최적성 증명으로 확대하지 않는다. 다수의 최적해가 존재하면 선택 ID의 일치보다 유효성·목적값·명시한 동률 정책을 비교한다.

## 방법별 유용한 독립 검사

| 대상 | 직접 재계산할 것 | 반례·경계 |
| --- | --- | --- |
| 경로 | 모든 연결의 존재·방향, 간선 비용 합, 도착점 | 불연결, 평행 간선, 0 비용, 음수 허용 범위 |
| 위상 순서 | 각 선행 관계가 반환 순서에서 앞서는지 | 고립점, 순환, 자기 루프 |
| 연결망·MST | 연결 성분·사이클·선택 간선 수, 작은 전체 조합 | 불연결 forest, 중복 간선, 동일 비용 |
| 매칭·흐름 | 허용 연결, 중복 배정, 유량 보존·용량·총비용 | 선택지 하나인 대상, 잔여 경로 재배정, 병목 |
| DP·선택 | 원래 항목으로 비용·가치·횟수 재계산 | 0 비용, 음수 가치, 동률, 빈 선택, 상태 중복 |
| 일정 | 실제 점유 구간과 준비 시간, 자원별 겹침·선후 관계 | 경계 시각, 야간·날짜 변경, 같은 시각 이벤트 |
| 공간·군집 | 후보의 실제 조건·좌표 단위, 전체 대상과 노이즈 | 좌표 순서, 경계·중복점, 고립 대상 |
| 개선·복구 | 전체 대상을 원본과 대조, 모든 영향받는 조건 | 한 대상 구제 때문에 다른 대상 누락, 오래된 예외 |
| 시뮬레이션 | 이벤트 순서, 유입·처리·잔여의 보존, 워밍업 | 같은 시각의 우선순위, 정지 조건, 편향된 시나리오 |

## 속성 검사의 전제

입력 순서를 바꿔도 최적 목적값은 같아야 하는 대칭적인 문제인지 먼저 확인한다. 동률 선택이나 입력 순서 기반 휴리스틱의 결과까지 같아야 한다고 단정하지 않는다.

필수 제약을 완화해 가능한 해 집합만 넓히고 목적을 그대로 유지한 최소화 문제라면 **정확한 최적값**은 악화되지 않는다. 그러나 제한 시간의 휴리스틱 결과는 악화될 수 있다. 이 경우 수학적 성질 위반으로 단정하기보다 기존 유효 해 보존·시드·후보·탐색 한도를 확인한다. 새 조건이 비용 정의까지 바꾸면 같은 성질을 적용할 수 없다.

작은 무작위 입력은 시드를 기록하고, 발견한 실패는 최소 사례로 축소해 회귀 검사에 남긴다. Hypothesis 같은 도구는 선택 사항이다. 설치된 환경에서 이득이 있을 때 사용하고 일반 테스트만으로 충분한 기능에 의존성을 추가하지 않는다. [Hypothesis 공식 문서](https://hypothesis.readthedocs.io/en/latest/)

## 종료 상태와 증거 범위

솔버의 실제 반환 상태·해·한계 정보를 그대로 읽는다. CP-SAT은 유효 해 발견, 최적 확인, 불가능 증명, 미확정, 모델 오류를 구별한다. 시간·메모리 제한으로 멈춘 미확정 상태를 불가능으로 번역하지 않는다. [CP-SAT 상태 설명](https://developers.google.com/optimization/cp/cp_solver)

목적값·최선의 경계·gap은 동일한 모델·단위·방향에서 해석한다. 후보를 일부 잘라 만든 모델의 최적성 또는 불가능성은 원래 전체 문제의 증명이 아니다. 라이브러리별 상태 코드는 다를 수 있으므로 하나의 숫자 규약을 공통으로 가정하지 않는다. [SciPy MILP 결과](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html)

경로 탐색의 성공이나 지역 최적점 도달만으로 전역 최적을 주장하지 않는다. 경로 솔버의 시간·해 개수 제한과 탐색 전략은 실제 품질·시간에 영향을 주므로 사용한 옵션을 기록한다. [경로 탐색 옵션](https://developers.google.com/optimization/routing/routing_options)

## 시간·규모·메모리

- 계산 함수 시간과 전체 요청 시간을 구분한다. 파일 읽기, 후보 생성, 모델 생성, 계산, 독립 검증, 저장·응답 중 실제 측정한 구간을 적는다.
- 같은 입력·설정·정책·자원 한도를 사용한다. 워밍업·캐시·프로세스 시작·스레드 수·시드가 다르면 숨기지 않는다.
- 작은 함수의 반복 측정에는 `timeit`을 쓸 수 있다. 서비스 전체 지연이나 입력을 변경하는 작업을 그대로 반복해 같은 의미라고 보지 않는다. [Python timeit](https://docs.python.org/3/library/timeit.html)
- 계산량 기호는 구현의 연산·저장 규모를 예상하는 근거다. Python의 큰 객체 비용, 희소·밀집 여부, 패키지 구현에 따라 실제 한계가 달라진다. 근거 없는 고정 행 수를 모든 환경의 안전 한도로 쓰지 않는다.
- 정확한 검산이 어려운 크기에서는 필수 조건의 전체 검사, 유효 기준선과 비교, 가능한 하한·상한, 서로 다른 방법의 비교를 결합한다. 좋은 결과를 찾았다는 주장과 최적성 증명을 구별한다.

선택한 변경이 통과하고 관련 우려가 해소되면 같은 검사를 이유 없이 반복하지 않는다. 마지막에는 실제 서비스에서 저장·표시되는 소스와 결과가 검증한 버전인지 확인한다.
